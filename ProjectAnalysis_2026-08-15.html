一、项目内容：这是什么游戏

Chaotic Chess 是一款本地双人热座（Hot-Seat）六边形战棋游戏。核心乐趣一句话：7 个棋子分 2 点 AP 的资源取舍 + 用道具改造棋盘本身的战场博弈。

完整对局流程

阶段内容
选棋子P1/P2 各自从棋子池选 7 个上场（9 种棋子：战士/骑士/弓手/法师/刺客/重装/牧师/游侠/术士）
部署半场划分部署（P1: r≥0，P2: r<0），初始棋盘为半径 4 的六边形（61 格）
对战回合制：每回合 +2 AP（上限 4）→ 移动(-1AP)/攻击(-1AP)/买装备(0AP)/用道具(0AP+命中-1AP)/大招(-1AP)
结算伤害实时产金币（造成×1.0 / 受到×0.3）；一方棋子全灭判负

二、框架：架构是怎么搭的

项目采用 MVC 三件套 × 每模块 + ScriptableObject 数据层 + 策略模式（Provider/Effect）。Model 层是纯 C# 类（无 Unity 依赖，可单测），Controller 是单例 MonoBehaviour 做协调，View 订阅 Model 事件渲染。这套结构在独立游戏里属于上游水平。

几个值得称道的设计决策

① 元素反应做到了"元素量"深度。原神式的 Gauge 消耗算法（触发方克底方有效值×2、消耗减半、余量决定新附着）——在独立战棋里属于超纲设计，但它让"附着状态"成为可博弈的资源，而不是简单的增伤开关。这是本作差异化最大的系统。
② 可插拔范围 Provider + SO 资产。攻击范围从"一个 int"升级为"类名+JSON 参数+baseRange"的 SO 资产，Circle_1~4 / MinMax_2_5 / Area_1_2 / Cone_60_3 等 12 个资产可跨棋子复用，弓手（MinMax 2-5 近身不可打）这类差异化即时可用。方案与 Ultimate/Passive 同构，心智统一。
③ 边界处理是"防御性编程"范本。动画期间屏蔽点击、冻结拦截选中、超导减防"当次攻击预应用"、溅射取 View 位置防销毁后取空、DoT 致死移出迭代集合——这些坑都是真实踩过才写得出来的。
④ 途经点路径规划。右键多途经点 + 分段最短路径 + 剩余步数动态重算 + 预览线，把移动从"点一下就走"升级成"规划路线"，配合攻击范围刷新，决策深度上了一个台阶。

四、游戏设计评估（以设计师视角）

Fun Hypothesis 验证

原假设："有限 AP 的多棋子取舍 + 动态棋盘 + 城邦差异化"。当前实现验证了前两条，第三条（城邦）尚未落地。

Pillar落地情况评估
1. 每回合 AP 分配难题7 棋子 2 AP（29% 激活率）+ AP 上限 4 不滚存成立 取舍感强，但激活率偏低，后期大件装备可能拖节奏——需 playtest 验证单局时长
2. 战场由玩家塑造扩展石/删除石/传送石已实现，格子增删有"只能邻接添加"约束成立 这是差异化核心，务必保
3. 城邦差异化对局未实现（仅 ReactionDatabaseSO 铺路）悬空 若砍掉它，Pillar 3 要改写，且与元素系统深度绑定需早做决策
4. 装备=战术扩展被动接口已接入伤害结算链（IReactionModifier），但有实际效果的装备少半程 目前多数装备仍是数值加成（+HP/+攻），"改变行为"的装备是下一阶段内容重点
5. 信息透明无战争迷雾，全量信息成立 与热座模式匹配

经济系统：Sources & Sinks

方向项目备注
Sources造成伤害×1.0 / 受到伤害×0.3 / 初始 50"受击 0.3"防止站桩赚钱，方向正确
Sinks装备购买 / 棋盘道具 / 未来城邦消费当前 Sink 单一：装备池只有 4 件，金币后期大概率溢出 → 通胀风险被设计文档自己标红
设计层最大风险：经济通胀。伤害收入 1:1 绑定伤害，而装备又叠攻击力 → 伤害↑ → 金币↑ → 更贵装备 → 伤害↑↑ 的正反馈。减法公式（atk-def 保底 1）下攻防差超过阈值后曲线会陡。建议：① 设单回合金币收入上限；② 装备属性严格 +1~+5（文档已写，需执行）；③ 提前规划装备/道具 Sink 池（至少 12+ 件）。

数值状态：诚实标注

核心数值（AP2/4、初始金币 50、伤害 1:1、能量 5/15/100）在《设计分析报告》中全部标注 [PLACEHOLDER] 并附 rationale——这符合"未经 playtest 不写死"的设计纪律，值得保持。但注意：该报告是 8/6 生成的，之后的范围 Provider、溅射公式、元素 Gauge 参数（如普攻触发量=1、克制×2）是新增数值，尚未补进同一张数值表——建议立刻同步，否则数值表失真。
