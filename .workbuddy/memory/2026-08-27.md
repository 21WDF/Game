## 背包系统（道具库存）启动

用户推进背包系统，作为季风之城三期气候复杂组（飓风掉落物拾取）的前置。需求（金铲铲式）：
1. 物品栏放到屏幕一侧（常驻）。
2. 装备拖拽给棋子装备。
3. 道具：可直接使用的双击直接用；需配合棋子的拖拽到棋子使用。

### 核对现状（关键事实）
- 装备有背包（`EquipmentManager._backpack` 双方各一个）+ `EquipToPiece`/`UnequipFromPiece`/`GetBackpack` + `OnEquipmentChanged`；交互是 `UI_EquipmentPanel`（E 键弹窗，按钮式装备/卸下，**无拖拽**）。
- 道具**无库存**：`GridItemManager.BuyAndUse` 是「扣金币→立即瞄准→命中执行/取消退金币」，`GridItemData` 注释明写「购买即用，无库存」。
- 项目**零拖拽代码**（grep IBeginDragHandler 等全空）——拖拽是全新交互层，且是 UI→3D 跨空间拖放（风险最高）。
- 棋子**无独立 Collider**：点击/悬停走 `RaycastTile` 命中格子 → `GetPieceAt(coord)` 取棋子。所以「拖到棋子」= 松手射线命中格子→取棋子，与点击选中棋子同套。
- 「需配合棋子 vs 直接使用」有现成判据：`GridItemData.requiresSelectedPiece`（传送石=true，扩展石/删除石=false）。
- **常驻侧栏与面板开闭计数的冲突**：`InputHandler.RegisterPanelOpen/Close` 计数机制，任何面板打开即 `IsAnyPanelOpen=true` → 全局屏蔽棋盘。常驻侧栏若走这套会锁死棋盘，必须不走计数、只挂 `UIPanelRaycastBlocker` 挡穿透。

### 用户拍板（4 决策）
1. 侧栏形态：**常驻**（金铲铲式，随活动玩家切换）。
2. 旧 `UI_EquipmentPanel`：**替换成新侧栏**（不并存两套装备 UI）。
3. 拆期：**一期数据链路**（道具库存 + 商店买道具进背包 + 侧栏点击式），拖拽/双击二期。
4. 道具堆叠：**每件占一格**（不堆叠）。
