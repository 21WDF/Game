## 背包系统 5 问题调整（tooltip 定位/关闭、满槽禁买、空槽高亮、拖拽目标格高亮）

用户集中反馈背包侧栏闭环后的 5 个交互/规则问题，要求调整。本次只诊断 + 出提示词，未动代码。

### 诊断结论（逐行核对现状后）
1. **tooltip 位置**：根因 `UI_ItemTooltip.PlaceRightOfAnchor` 用「物品格右边缘」定位，应改「Scroll View 右边缘 + 与物品格垂直平齐」。
2. **tooltip 关闭**：根因关闭逻辑挂「移出物品格」（三态延迟关），应改双条件「离开滚动视图区域 且 不在 tooltip 上」才关。
3. **满槽禁买**：根因 `EquipmentManager.BuyEquipment` / `GridItemManager.BuyToInventory` 只查金币、不查容量；容量只在侧栏 UI 层由 slotCount=10 双列推导（装备5/道具5），逻辑层拿不到。
4. **空槽高亮**：根因 `UI_BackpackSidebar.OnIconClicked` 对空槽也切高亮，应空槽无反应。
5. **拖拽目标高亮**：根因拖拽无目标格反馈；应拖拽开始常亮「可施加棋子」所在格（战术层）、颜色进 GameConfig、悬停走现有默认 hover 层、松手判定与高亮收集共用统一目标谓词（当前=己方，预留「可对敌方」扩展）。

### 用户拍板（2 决策）
1. **容量来源**：进 GameConfig 统一（装备容量/道具容量字段，默认各 5），侧栏槽位生成 + 购买拦截都读它，单一事实来源。
2. **拖拽目标格高亮颜色**：浅金色（进 GameConfig，可调）。

### 已出提示词 `背包系统问题调整_Trae提示词.md`

### 回归 bug（需修，P1）
**`UI_BackpackIconSlot.OnPointerExit` 第149行：`if (HasItem && Tooltip != null) Tooltip.NotifyPointerLeftScrollArea();`** —— 空槽（HasItem=false）退出时**不通知**「离开滚动区」，导致 `_pointerInScrollArea` 卡 true。
- 触发：右键看装备 tooltip → 鼠标经过空槽 → 从空槽移出滚动视图/移到侧栏背景 → tooltip 永不关。
- 根因：Trae 把「空槽不响应」的 HasItem 判断错误扩展到了 OnPointerExit（旧版 OnPointerExit 是无条件的）。「空槽不响应」只该作用于 OnPointerClick。
- 修复方向：OnPointerExit 去掉 HasItem 条件，无条件 `NotifyPointerLeftScrollArea`（离开格子=可能离开滚动区→延迟关，靠下一格 Enter 取消；这正是旧版正确逻辑）。

### 非致命小瑕疵

2. `CanApplyDragTarget` 签名只有 `(side,piece)` 无负载参数，将来「可对敌方」扩展需加负载参数（当前功能正确，扩展点预留不完整）。
3. `GridItemManager.BuyToInventory` 没复用 Awake 已缓存的 `_config`、`EquipmentManager` 每次 `Resources.Load`——低频操作功能正确，效率小瑕疵。
