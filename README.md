# Chaotic Chess · 回合制 3D 战棋原型

> 一款 2 人对战的六边形战棋原型。核心是**有限行动点 + 玩家共同塑造棋盘 + 城邦差异化对局**——棋盘不是固定的舞台，而是玩家可以用道具实时改造的资源。

## 玩法概览

```
选棋  →  部署  →  回合行动  →  金币结算  →  胜负判定
         ↑                            │
         └──── 棋盘可被道具改造 ────────┘
```

- 双方各操控多枚棋子，在六边形棋盘上轮流行动
- 行动点（AP）是唯一的行动资源：移动、攻击、使用道具都消耗 AP
- 造成 / 承受伤害都会产出金币，金币用于在商店购买装备与棋盘道具
- 本局生效城邦由**双方各排除 2 个城邦（排除法）**、在剩余候选里随机确定，城邦决定本局有哪些专属机制生效

| **棋盘与地图** | 半径 4 的六边形网格（61 格）；支持对局中动态增删地块；扩展格须邻接既有棋盘以保证连通性 |
| **棋盘道具** | 扩展石 / 删除石 / 传送石，3 种地块改造手段 |
| **范围与空间** | 6 种攻击范围（圆形 / 环形切线 / 直线 / 扇形 / 区域 / 最小最大距离）× 5 种移动方式（自由 / 直线 / 飞行 / 穿越 / 奇偶），以可插拔 Provider 实现 |
| **寻路** | BFS 移动范围计算、多途经点手动路径拼接，含总步数上限校验 |
| **元素反应** | 蒸发 / 融化 / 超载 / 感电 / 冻结 / 超导 6 种；单向克制表（水克火、火克冰）；整数型元素量（Gauge）消耗算法 |
| **资源与经济** | AP 每回合 +2、上限 4；金币双来源（造成伤害 +1 / 受击 +0.3）；装备与道具背包各 **10** 格 |
| **城邦** | 贸易 / 季风 / 元素 / 战争 4 个**已实现**；**欢愉（手牌）/ 邪疑（卧底·视野）设计成册、尚未实现**。已实现的含拍卖行 / 地下交易、雷电残留格、元素格等专属机制 |
| **棋子** | 10 个棋子角色，各自独立数值、先天元素、内建被动与专属大招 |
| **被动与装备** | **24 件**装备、**装备被动 19 种 + 角色被动 11 种**；棋子被动与装备被动共用同一套 `PassiveFactory` |
| **大招与能量** | 能量满即释放（阈值**逐棋子**：多数 100，杜林 60）；移动 +5 / 攻击 +15；支持敌方单体 / 自身增益 / 指定格子三类目标模式；甘雨以**蓄力层数**替代能量条 |
| **元素格** | 大招可将作用范围内格子转为元素格，持续若干回合 |
| **棋子表现** | 全程序化动作（攻击前冲 / 受击抖动 / 死亡缩放 / 召唤出现）+ 零素材视觉反馈（受击闪白 / 元素附着光环 / 反应脉冲 / 大招扩散）；**不依赖动画文件与特效素材**，动作由 DOTween 驱动 |
| **大厅与对局配置** | 独立大厅场景为正式入口；开局前配置棋盘半径（4/5/6）、每方棋子数（3/5/7）、城邦模式（随机城邦 / 无城邦）。**城邦排除法选择**（双方各划掉 2 个，6 个城邦取剩余候选随机定 1 个）与结算均在开局前完成 |
| **玩家档案与金币** | 本地账号档案（密码 SHA256 + 盐哈希存储，认证走 `IAuthProvider` 接口、预留联机替换）；局外金币：每局 +100、胜 **+300** / 平 **+150** / 负 +100（平局档为设计，代码待落地）；金币用于购买棋子解锁棋池，**棋池数量决定「每方棋子数」选项的解锁**（拥有数 ≥ 该选项值才可选） |

## 几个值得一说的设计点

### 1. 元素量（Gauge）用整数而非浮点

```
有效值：克制方 ×2
消耗量 = min(底元素有效值, 触发元素有效值)
实际消耗：克制方消耗减半，保底 1
```

用整数是为了**结算可复现**——同样的输入必然得到同样的输出，便于复盘与平衡调试。

### 2. 反应数据外置为 ScriptableObject

`ElementReactionTable` 只负责算法，反应参数（倍率、额外伤害、DoT、减防、冻结回合、击退格数）来自 `ReactionDatabase.asset`。**新增一种反应不需要改代码**，并预留 `IReactionModifier` 修饰器链接口供装备被动挂载。

### 3. 范围系统是三段式可插拔结构

棋子不直接持有"能打几格"，而是持有 `Provider 类名 + 构造参数 JSON + 基础范围`。`RangeProviderFactory` 按类名实例化，装备加成在基础范围上叠加后传入。因此**同一套棋子数据能组合出差异很大的空间手感与战术定位**。

### 4. 城邦是"本局变量"而不是"角色阵营"

开局双方各排除 2 个城邦（排除法）→ 在剩余候选里随机确定本局生效城邦。这让同一套棋子在不同对局里呈现不同的强度与节奏，也是"城邦差异化对局"的落地方式。

## 快速开始

**环境**

- Unity **6000.3.19f1**（Universal Render Pipeline 17.3.0）
- 依赖：Input System、TextMesh Pro、DOTween

**运行**

1. 用 Unity Hub 以 6000.3.19f1 打开本项目（首次打开需等待资源导入）
2. 打开 `Assets/Scenes/MainMenu.unity`（**大厅**：对局配置 + 城邦排除 + 开始游戏）
3. 进入 Play 模式，点「开始游戏」进入对局

> **调试捷径**：也可直接打开 `Assets/Scenes/SampleScene.unity` 按 Play —— 会跳过大厅、以默认配置开局（本局无城邦），省去每次过大厅的步骤。

**操作**

| 键位 | 作用 |
|---|---|
| 左键 | 选中棋子 / 确认落点 |
| `R` | 在移动范围与攻击范围高亮之间切换 |
| `U` | 释放大招（能量或蓄力满足时） |
| 结束回合按钮 | 结束当前玩家的回合 |

## 技术栈

- **引擎**：Unity 6000.3.19f1（URP，PC / Mobile 双渲染配置）
- **语言**：C#
- **架构**：MVC 分层；工厂 + 策略模式（范围 Provider / 被动效果）；ScriptableObject 全数据驱动
