## 2. 系统概述

### 2.1 目的

把"攻击力 vs 防御力"变成**可预期的一串数字**，并让**元素反应、装备被动、护盾、减伤**都有介入点。

这是设计支柱 **P2（反应链可预期、结果可复现）** 的基础——**同一个输入必得同一个输出**，玩家才能复盘"我为什么死了"。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **伤害可心算** | 减法公式 + 保底 1，玩家能大致估出"这一击大概打多少" |
| **输得明白** | 跳字显示实际伤害；魔法/真实伤害能"无视防御"被感知到 |
| **永远打得动** | **保底 1 点**——不存在"完全打不动"的僵局 |

### 2.3 在整体中的位置

```
攻击力 / 防御力（棋子 + 装备）
      ↓
伤害计算（本册）— 基础公式 + 反应倍率 + 减伤链
      ↓
元素反应（提供 DamageMultiplier / ExtraDamage）
      ↓
扣血 → 死亡判定 → 金币产出 → 跳字反馈
```

## 3. 核心规则

### 3.1 基础公式（已核实）

```
baseDamage = max(1, attack - defense)
```

**减法公式**：攻击力减去防御力，**保底 1 点**。

> **为什么保底 1**：如果允许打出 0 伤害，那么"高防单位 vs 低攻单位"会变成无解的僵局（打不动、也打不完），对局可能卡住。保底 1 保证了**任何攻击都有推进作用**。

### 3.2 含元素反应的公式（已核实）

```
reaction  = GetReaction(防御方附着元素, 攻击方先天元素, 棋子修饰器链)
damage    = max(1, round(baseDamage × reaction.DamageMultiplier) + reaction.ExtraDamage)
```

**关键细节**：

| 细节 | 说明 |
|---|---|
| **倍率作用于 `baseDamage`** | 不是作用于 `attack`——防御力在倍率之前就已扣除 |
| **`ExtraDamage` 在倍率之后加** | 固定加值不吃倍率 |
| **最终仍保底 1** | 即使倍率为 0、ExtraDamage 为负，也不会打出 0 |
| **无反应时** | `DamageMultiplier = 1.0`、`ExtraDamage = 0`（配置为 None） |

### 3.3 伤害类型 × 防御（决策 D6 的落地）

**伤害类型（`DamageKind`）与防御/护盾的关系**：

| 伤害类型 | 受防御减伤 | 受护盾拦截 | 触发反甲 |
|---|---|---|---|
| **物理** `Physical` | ✓ | ✓ | ✓ |
| **魔法** `Magical` | ✗ | ✓ | ✗ |
| **真实** `True` | ✗ | ✗ | ✗ |

**实现方式**：减伤统一走 `GetTotalDamageReduction(target, kind)`，**函数内部按 `kind` 筛选**——魔法/真实返回 0（不减防）。

```
damage = max(1, damage - GetTotalDamageReduction(target, damageKind))
```

> **⚠️ 伤害类型 与 元素附着 是正交维度**（总案 D6）：物理伤害**也可以带元素**。
> 例：克洛琳德的路径伤害 = **物理类型 + 雷元素**；杜林溅射 = 物理 + 火。
> **不要把"物理"误解为"无元素"**——这是最容易搞错的地方。

### 3.4 伤害来源（`DamageSource`，位掩码）

| 来源 | 值 | 说明 |
|---|---|---|
| `Attack` | 1 | 普攻 |
| `Splash` | 2 | 元素 + 非元素溅射 |
| `Ultimate` | 4 | 大招 |
| `Dot` | 8 | 感电 DoT / 环境伤害 |
| `Reflect` | 16 | 反伤 |

**用途**：受击表现分级（完整 vs 轻量）、被动筛选、金币归属判定。**是位掩码**，可组合（如 `Attack | Splash`）。

> **注意区分**：`DamageSource`（来源维度）与 `DamageKind`（类型维度）**是两个独立的枚举**——前者回答"从哪来"，后者回答"是什么性质"。

## 4. 数值与公式

### 4.1 主公式汇总

| 场景 | 公式 |
|---|---|
| 基础伤害 | `max(1, attack - defense)` |
| 带反应 | `max(1, round(baseDamage × multiplier) + extra)` |
| 减伤后 | `max(1, damage - reduction(kind))` |
| 易伤 | `ApplyVulnerability(target, ref damage)`（具体系数见 §10） |

### 4.2 演算示例

**例 1：普攻无反应**（攻击 20、防御 5）

```
baseDamage = max(1, 20 - 5) = 15
无反应 → multiplier = 1.0、extra = 0
damage = max(1, 15 × 1.0 + 0) = 15
```

**例 2：蒸发反应**（假设蒸发 multiplier = 1.5、extra = 0）

```
攻击 20、防御 5 → baseDamage = 15
damage = max(1, round(15 × 1.5) + 0) = round(22.5) = 23
未反应 15 → 蒸发 23，提升 53%
```

**例 3：防御力很高**（攻击 10、防御 30）

```
baseDamage = max(1, 10 - 30) = 1（保底生效）
即使蒸发：damage = max(1, round(1 × 1.5)) = 2
```

> **观察**：保底 1 让"低攻打高防"仍有伤害，但**极低**——这类情况下想突破需要**忽略防御的手段**（魔法/真实伤害、超导减防、固定伤害 `ExtraDamage`）。

**例 4：超导减防的时序**（源码注释明确）

```
超导的 DefenseReduction 在伤害计算【之前】预设到目标身上：
  AttackPiece 流程：查反应 → 若 DefenseReduction > 0 则预设到 target → 用同一反应配置算伤害
→ 当次攻击【即享受】减防收益（不是下一次才生效）
```

**例 5：额外固定伤害的价值**（攻击 10、防御 30、某反应 extra = 10）

```
baseDamage = max(1, 10-30) = 1
damage = max(1, round(1 × 1.0) + 10) = 11
```

> **结论**：`ExtraDamage`（固定加值）**在"打不动"的局面下价值极高**——它是绕过防御的主要手段之一。

### 4.3 减法公式的平衡特性（必须知道的副作用）

减法公式有一个**递增收益**特性：

| 防御值 | 面对攻击 20 时 | 减伤比例 |
|---|---|---|
| 0 | 20 | 0% |
| 5 | 15 | 25% |
| 10 | 10 | 50% |
| 15 | 5 | 75% |
| 19 | 1 | 95% |

**防御力的边际收益是递增的**——从 15 加到 19（+4）把减伤从 75% 提到 95%。

> **这意味着什么**：**堆防御的收益可能过高**，尤其配合"保底 1"时，防御能形成接近免疫的效果。而乘法公式（如 `damage × (1 - def/(def+K))`）的防御收益是递减的，不会出现这种情况。
>
> **建议**：playtest 时重点观察"高防棋子是否过强"。若出现过强，**优先考虑换乘法公式**（这是结构性改动，需谨慎），或限制防御的装备加成上限。

## 5. 数据结构（字段定义表）

### 5.1 `DamageKind`（伤害类型）

| 枚举值 | 中文 | 受防御 | 受护盾 |
|---|---|---|---|
| `Physical` | 物理 | ✓ | ✓ |
| `Magical` | 魔法 | ✗ | ✓ |
| `True` | 真实 | ✗ | ✗ |

### 5.2 `DamageSource`（伤害来源，位掩码）

| 枚举值 | 值 | 中文 |
|---|---|---|
| `Attack` | 1 | 普攻 |
| `Splash` | 2 | 溅射 |
| `Ultimate` | 4 | 大招 |
| `Dot` | 8 | 持续/环境伤害 |
| `Reflect` | 16 | 反伤 |

### 5.3 `ReactionConfig` 中与伤害相关的字段

（完整字段见《元素反应》分册）

| 字段中文名 | 字段英文名 | 类型 | 作用 |
|---|---|---|---|
| 伤害倍率 | `DamageMultiplier` | float | 乘在 `baseDamage` 上 |
| 是否清除底元素 | `ClearBase` | bool | 本阶段不单独使用（覆盖即消耗） |
| 额外固定伤害 | `ExtraDamage` | int | **倍率之后**加，不吃倍率 |

### 5.4 `DamageCalculator`（静态工具类）

| 方法 | 签名 | 说明 |
|---|---|---|
| `Calculate` | `int Calculate(int attack, int defense)` | 基础公式（无反应） |
| `CalculateWithElement` | `(int damage, ReactionConfig reaction) CalculateWithElement(attack, defense, attackerElement, defenderAffixed, pieceModifiers = null)` | 查反应 + 算伤害（返回反应配置供后续使用） |
| `CalculateWithReaction` | `int CalculateWithReaction(attack, defense, reaction)` | **用预查询的反应配置算伤害**——供"先查反应 → 预设超导减防 → 再用同一配置算伤害"的流程使用 |

> **为什么有 `CalculateWithReaction`**：`AttackPiece` 需要"先知道是什么反应，才能把超导减防预设到目标身上，再算伤害"。如果每次重查反应，会查两次；且超导减防一旦提前应用，第二次查询结果可能已变。这个重载就是为解决这个时序问题。

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| 攻击 < 防御 | 打出保底 **1** 点 | ✓ |
| 倍率为 0 | 仍保底 1 | ✓ |
| 魔法/真实伤害遇高防 | 不减防（`GetTotalDamageReduction` 返回 0） | ✓ |
| 真实伤害遇护盾 | **穿过护盾** | ✓（按 D6） |
| 超导减防的生效时机 | 当次攻击即享受（在算伤害前预设） | ✓ |
| 伤害计算出现 0 或负 | **不应发生**（两层 `max(1, ...)`） | ✓ |
| 护盾拦截的时序 | 拦在减伤之前（拦截原始伤害） | ⚠️ 见 §10 |
| 减伤链的完整顺序 | 护盾 → 减伤 → 易伤 → 首伤=1 → 延迟拆分 → 扣血 → 免死 | ⚠️ **顺序待核实**（见 §10） |
