## 2. 系统概述

### 2.1 目的

大招是**局内的情绪高点**——它需要一个"攒"的过程（能量），以及一个"放"的决策（什么时候值得用）。

回答两个问题：**"我什么时候能放大招？"**、**"这一发打出去值不值？"**

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **积攒可感知** | 能量条/蓄力层数在 HUD 上可见，玩家能预期"再打两下就能放" |
| **释放有仪式感** | 释放瞬间有独立的视觉反馈（扩散光环），与普攻区分开 |
| **决策有分量** | 释放消耗 AP，所以"放不放大招"本身是个取舍 |

### 2.3 在整体中的位置

```
移动 / 攻击 → 积累能量
      ↓
大招（本册）— 消耗能量 + 1 AP 释放
      ↓
伤害 / 增益 / 召唤 / 元素格生成
      ↓
元素反应 · 战局转折
```

## 3. 核心规则

### 3.1 两套资源模型（同一套框架）

**大部分棋子用「能量」**，**甘雨用「蓄力层数」**——这是决策 **D2** 的落地。

| 模型 | 字段 | 驱动方式 | 使用者 |
|---|---|---|---|
| **能量** | `EnergyModel`（0~`MaxEnergy`） | 移动 +5 / 攻击 +15 / 被动回能 | 多数棋子 |
| **蓄力** | `usesChargeSystem` + `ChargeStacks`（0~`maxChargeStacks`） | **蓄力层数驱动**，无能量条 | 甘雨 |

> **为什么给甘雨换一套**：能量是"做什么都涨"的通用资源；蓄力是"**必须选择蓄力这个动作**"的资源——它把"狙击手需要耐心"这个定位写进了资源模型里，而不是只改数值。

### 3.2 能量规则

| 规则 | 值 | 配置字段 |
|---|---|---|
| 能量上限 | **100** | `UltimateConfig.energyRequired` |
| 移动获得 | **+5 / 次** | `UltimateConfig.energyPerMove` |
| 攻击获得 | **+15 / 次** | `UltimateConfig.energyPerAttack` |
| 每回合回能 | `PieceData.baseEnergyRegen`（默认 0，按棋子配） | 棋子字段 |
| 满能判定 | `CurrentEnergy >= MaxEnergy` | `EnergyModel.IsFull` |

**释放条件**：**满能 + 消耗 1 AP**（源码注释：`消耗满能量 + 1 AP`）。

### 3.3 三类目标模式

| 模式 | 语义 | 对应旧字段 | 效果入口 |
|---|---|---|---|
| **Enemy** | 敌方棋子（默认） | `requiresTarget = true` | 两参 `Execute(caster, target)` |
| **Self** | 自身增益 | `requiresTarget = false` | 两参 `Execute(caster, caster)` |
| **Tile** | 指定格子（**可点空格**） | — | **三参** `Execute(caster, target, targetCoord)` |

**Tile 模式的高亮形状**（`UltimateTileShape`）：

| 形状 | 语义 |
|---|---|
| `Circle` | 以自身为圆心的圆形（默认）；**含被占格**（效果自行决定合法性） |
| `Ray` | **6 方向射线上的空格**（直线冲刺/落点类）；被占格不可选，点击被占格自然取消 |

> `Ray` 的射线长度 = `tileTargetRange`；**必须 > 0**，否则没有可选格、无法释放。

### 3.4 部分能量消耗（`IPartialEnergyUltimate`）

**释放条件仍是「满能」**，但**消耗量由效果自己决定**。

**典型用例**（源码注释举的例子）：**菲林斯**
- **强化态** → 只消耗 `empoweredEnergyCost`，**保留剩余能量**
- **普通态** → 全清

**实现**：`PieceManager.UseUltimateCore` 在能量校验阶段创建效果后询问 `GetEnergyCost(caster)`；**未实现该接口的大招走 `TryConsume()`（满能全清）**——原行为零影响。

> **这是"开闭扩展"的一个好例子**：不改既有大招，用接口给特定棋子开了口子。

### 3.5 元素格生成（`IUltimateAreaProvider`）

勾选 `enableElementTiles` 后，大招释放时会把**作用范围内全部格子**替换为**释放者先天元素的元素格**。

**统一入口设计**：

```
大招效果类「只声明我影响了哪些格子」（IUltimateAreaProvider.GetUltimateArea）
      ↓
替换由 ElementTileManager 统一完成（各大招不各写一套替换逻辑）
```

| 要点 | 说明 |
|---|---|
| **范围口径** | 大招的**完整几何作用范围**——不区分效果性质、**不排除被占据的格子** |
| 直线穿透型 | 整条射线 |
| 指定格 AOE 型 | 该区域全部格 |
| 自身圆形型 | 整个圆内全部格 |
| **调用时机** | 在 `Execute` **之前**调用（释放者位置/蓄力层数等仍是释放前状态，与效果内部的范围计算**同源同参数**）；`Execute` 完成后统一应用 |
| 未实现该接口 | 勾选元素格子配置时**不产生任何替换**，并**告警一次**提示适配缺失 |

> **"告警一次"是个好设计**：不是静默失效，而是明确告诉开发者"这个大招勾了元素格但没实现范围声明"。

## 4. 数值与公式

### 4.1 能量积攒速率

```
单次移动贡献 = energyPerMove = 5
单次攻击贡献 = energyPerAttack = 15
满能需求     = 100
```

**演算：纯攻击攒满**
```
100 ÷ 15 = 6.67 → 第 7 次攻击时满能
```

**演算：纯移动攒满**
```
100 ÷ 5 = 20 次移动
```

**演算：典型混合节奏（推荐关注这个）**

假设一个棋子每回合移动 2 格 + 攻击 1 次：

```
每回合能量 = 2 × 5 + 1 × 15 = 10 + 15 = 25
满能所需回合 = 100 ÷ 25 = 4 回合（Turn）
```

> **这意味着**：在"每回合动 2 格打 1 次"的节奏下，**大约每 4 个 Turn（2 个 Round）能放一次大招**。
> 若一个 Round 约 1 分钟，则**约每 2 分钟一次大招**——这是节奏的关键参数。
> **如果实测觉得大招太频繁**（每次都能放，失去"攒"的意义）→ 提高 `energyRequired` 或降低 `energyPerAttack`。

### 4.2 若棋子有被动回能

`PieceData.baseEnergyRegen` 会让满能更快。例如 +5/回合：

```
每回合能量 = 25 + 5 = 30 → 满能所需 ≈ 3.33 回合
```

> **这类被动对"大招节奏"的影响是加速的**——设计带回能被动的棋子时要注意它可能把大招从"两分钟一次"变成"一分半一次"。

### 4.3 部分能量消耗的影响（菲林斯式）

若某大招在特定状态下只消耗 50% 能量并保留剩余：

```
第一次释放（强化态）：耗 50 → 剩余 50
之后只需再攒 50 即可再次释放 → 大招频率翻倍
```

> **这是"强化态"的强度来源**——它不只是让大招更强，还让**下一次大招来得更快**。评估棋子强度时要把这个"频率提升"算进去。

## 5. 数据结构（字段定义表）

### 5.1 枚举

| 枚举 | 值 | 说明 |
|---|---|---|
| `UltimateTargetMode` | `Enemy` / `Self` / `Tile` | 三类目标模式 |
| `UltimateTileShape` | `Circle` / `Ray` | Tile 模式的高亮形状 |

### 5.2 `UltimateConfig`（PieceData 内嵌类）

| 字段中文名 | 字段英文名 | 类型 | 默认 | 注释 |
|---|---|---|---|---|
| 大招名 | `ultimateName` | string | `""` | 显示用 |
| 能量需求 | `energyRequired` | int | **100** | 满能阈值 |
| 每次移动获能 | `energyPerMove` | int | **5** | |
| 每次攻击获能 | `energyPerAttack` | int | **15** | |
| 是否需目标 | `requiresTarget` | bool | `true` | 旧语义（Enemy 模式） |
| 目标模式 | `targetMode` | UltimateTargetMode | — | 新语义（三类） |
| 格子目标距离 | `tileTargetRange` | int | **0** | Tile 模式可点范围（Ray 需 > 0） |
| 效果类名 | `effectClassName` | string | `""` | `IUltimateEffect` 实现类名 |
| 效果参数 | `effectJsonParams` | string | `""` | JSON |
| 启用元素格 | `enableElementTiles` | bool | `false` | 释放后把作用范围转为元素格 |
| 元素格持续 | `elementTileDurationTurns` | int | **4** | 元素格持续回合数 |

### 5.3 `EnergyModel`

| 成员 | 类型 | 说明 |
|---|---|---|
| `MaxEnergy` | int（只读） | 能量上限（构造时注入） |
| `CurrentEnergy` | int（只读） | 当前能量 |
| `IsFull` | bool（只读） | `CurrentEnergy >= MaxEnergy` |
| `OnEnergyChanged` | `event Action<int>` | 能量变化（UI 订阅） |
| `Gain(amount)` | void | 增加能量（自动封顶） |
| `TryConsume()` | bool | **满能全清**（默认释放路径） |
| `TryConsume(amount)` | bool | **部分消耗**（供 `IPartialEnergyUltimate`） |

### 5.4 三个大招接口

| 接口 | 成员 | 职责 |
|---|---|---|
| `IUltimateEffect` | `Execute(caster, target)`<br>`Execute(caster, target, targetCoord)`（**默认委托两参**） | 大招行为契约 |
| `IPartialEnergyUltimate` | `GetEnergyCost(caster)` | 部分能量消耗（释放条件仍满能） |
| `IUltimateAreaProvider` | `GetUltimateArea(caster, target, targetCoord?)` | **声明**作用范围（供元素格统一替换） |

> **`Execute` 三参版本的默认实现**是 `=> Execute(caster, target)` ——**现有大招零改动**，只有格子型大招（召唤/领域/指定位 AOE）覆写它。这是"向后兼容的接口扩展"写法。

### 5.5 现有大招实现（11 个）

| 类名 | 附带接口 | 推测用途 |
|---|---|---|
| `FireSlashUltimate` | `IUltimateAreaProvider` | 烈焰斩（战士） |
| `IceBarrierUltimate` | `IUltimateAreaProvider` | 冰障（法师） |
| `FlameLanceUltimate` | `IUltimateAreaProvider` | 炎枪 |
| `FrostArrowUltimate` | `IUltimateAreaProvider` | 霜箭（狙击） |
| `FrostFeastUltimate` | `IUltimateAreaProvider` | 霜宴 |
| `ThunderSweepUltimate` | **`IPartialEnergyUltimate`** + `IUltimateAreaProvider` | 雷扫（**部分能量消耗**） |
| `ThunderDashUltimate` | `IUltimateAreaProvider` | 雷驰（冲刺） |
| `MusouStrikeUltimate` | `IUltimateAreaProvider` | 无想的一刀 |
| `TideSurgeUltimate` | `IUltimateAreaProvider` | 潮涌 |
| `OmenUltimate` | `IUltimateAreaProvider` | 预兆 |
| `BaronBunnyUltimate` | `IUltimateAreaProvider` | 兔兔伯爵（**召唤**） |

## 6. 配置方式

| 配置项 | 位置 |
|---|---|
| 大招配置 | `PieceData.ultimateConfig`（Inspector 内联） |
| 效果实现 | `Assets/Game/Piece/Effects/*Ultimate.cs` |
| 工厂 | `PieceManager.CreateUltimate(className, jsonParams)` |
| 能量上限/获取 | `UltimateConfig.energyRequired` / `energyPerMove` / `energyPerAttack` |
| 蓄力模型 | `PieceData.usesChargeSystem` / `maxChargeStacks` |
| 元素格 | `enableElementTiles` / `elementTileDurationTurns` + `ElementTileConfig` |

**新增一个大招**：写 `IUltimateEffect` 实现类 → 在棋子的 `effectClassName` 填类名 → 如需参数填 `effectJsonParams`。**不需要改 `PieceManager`**（工厂按类名创建）。

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| 能量未满时尝试释放 | 拒绝（UI 应禁用） | ✓ |
| 满能但 AP 不足 | **拒绝**（释放需 1 AP） | ✓ |
| Tile 模式 `tileTargetRange ≤ 0`（Ray） | **无可选格，无法释放** | ✓（源码注释明确） |
| Ray 模式点到被占格 | 自然取消 | ✓ |
| 勾选元素格但未实现 `IUltimateAreaProvider` | 不替换 + **告警一次** | ✓ |
| 部分能量消耗型：未实现接口 | 走 `TryConsume()` 满能全清（原行为） | ✓ |
| 大招打死目标 | 目标死亡流程正常触发（见《死亡与胜负》） | ✓ |
| 释放者在大招中移动（冲刺型） | 落点为终点（大招扩散锚点也在终点） | ✓ |
| 能量超过上限 | `Gain` 自动封顶 | ✓ |

## 10. 待确认项

1. **棋子 ↔ 大招的实际映射**：哪些棋子配了哪个大招？需查 `PieceData.ultimateConfig.effectClassName`（本文档 §5.5 的"推测用途"列未核实）
2. **哪些棋子配了 `baseEnergyRegen`**：回能被动会**加速大招节奏**（§4.2），需要盘一遍
3. **4 回合满能是否合适**（§4.1 演算）：这是大招频率的核心参数，需实机确认"是否太频繁/太稀少"
4. **菲林斯式部分消耗的具体数值**：`empoweredEnergyCost` 是多少？保留剩余意味着大招频率翻倍（§4.3），**评估强度时必须算进去**
5. **甘雨的蓄力层数如何获取**：是"蓄力动作"还是"某些行为叠层"？（D2 只说层数驱动大招，未说层数怎么涨）
6. **大招释放是否有名称/特效提示**：目前只有扩散光环
7. **7 个棋子的大招未实现**（总案 §9.2）：弓手箭雨 / 骑士冲锋 / 刺客背刺 / 牧师治疗 / 重装眩晕 / 术士召唤 / 游侠传送——现有 11 个大招类与实际棋子的覆盖关系待盘
