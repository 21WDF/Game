## 2. 系统概述

### 2.1 目的

商店是**局内金币的唯一去向**（sink）。

回答的问题：**"我这局赚的钱，怎么变成战力"**。

> **为什么 sink 很重要**（设计原则）：如果金币只涨不花（或花不出去），它会迅速失去意义——玩家不再关心"这一击能不能多赚点钱"。商店让金币的价值闭环。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **钱能变强** | 买装备/道具能立刻感受到战力变化 |
| **有取舍** | 背包只有 5+5 格 → 买什么必须选 |
| **城邦有专属货** | 城邦专属装备只在对应城邦的商店出现 → 城邦影响构筑 |

### 2.3 在整体中的位置

```
金币（造成/承受伤害获得）
      ↓
商店（本册）— 金币的 sink
      ↓
装备（属性加成 + 被动）· 棋盘道具（改造棋盘）
      ↓
战力变化 → 影响后续回合
```

## 3. 核心规则

### 3.1 三个商店

| 商店 | 入口 | 商品 | 特点 |
|---|---|---|---|
| **主商店** | `UI_ShopPanel` | 装备（`EquipmentData`）+ 棋盘道具（`GridItemData`） | **随时可买**（按 Tab 分类） |
| **拍卖行** | `AuctionManager` | 拍卖专属装备（`AuctionItemData` 包装） | **竞价机制**（见 §3.4） |
| **地下交易** | `UndergroundTradeManager` | 地下交易专属商品（`UndergroundItemData`） | **有开关条件**（`ShopOpen`），带"代价"类被动 |

> **拍卖行与地下交易都是「贸易城邦」的专属机制**（见城邦分册）——非贸易城邦下不开放。

### 3.2 主商店的 Tab 分类

`UI_ShopPanel` 用 `ShopTab` 枚举分类展示：

| Tab | 内容 |
|---|---|
| 基础 / 中级 / 高级 | 按 `EquipmentTier` 分类的常规装备 |
| **城邦**（`CityState`） | **城邦专属装备**（动态过滤，见 §3.3） |
| 道具 | 棋盘道具 |

### 3.3 ⚠️ 城邦装备池过滤（城邦差异化的落地）

```csharp
// UI_ShopPanel
private bool ShouldShowCityState(EquipmentData data) => manager.ShouldShowEquipment(data);
```

**过滤逻辑收敛在 `CityStateManager.ShouldShowEquipment(data)`**——这是**城邦过滤的单一入口**（与元素系统、战争之城同一种设计范式）。

**效果**：**城邦专属装备（`tier = CityState`）只在「当前城邦 == 该装备所属城邦」时出现在商店里**。

> **源码注释称此处为"城邦动态展示扩展点"** —— 意味着未来可能扩展为更复杂的动态规则（例如"城邦等级影响库存"）。

### 3.4 拍卖行机制

| 参数 | 值 | 说明 |
|---|---|---|
| 起拍价 | `startingPrice`（默认 **10**） | `AuctionItemData` |
| 最小加价 | `minIncrement`（默认 **5**） | 每次竞价的最少增幅 |
| 竞价入口 | `AuctionManager.PlaceBid(lot, side)` | 返回是否成功 |

**机制推断**（详见 §10 待确认）：双方对同一件商品竞价，**出价高者得**。由于是本地热座双人，形成"**金币的竞争性 sink**"——一件好装备被两人抬价，可能比定价商店更贵。

> **设计意义**：拍卖行把"买东西"从单人决策变成**双方博弈**——这是贸易城邦的核心特色。

### 3.5 地下交易机制

| 成员 | 说明 |
|---|---|
| `IsShopOpen(side)` | **该方的地下商店是否开放**（`_model.GetSide(side).ShopOpen`） |
| `BuyItem(side, item)` | 购买 |
| `UndergroundItemData` | 商品数据类型（独立于普通装备） |

**"代价"特征**：地下交易的商品带**代价类被动**（如 `BloodCostPassive` 血祭——扣血换收益）。记忆中有两处相关修复（"地下交易代价被动参数修复"、"地下交易激活时序修复"），说明这套机制涉及**参数配置与时序**的细节。

### 3.6 购买流程（主商店）

```
玩家点击商品
   ↓
UI_ShopPanel 校验（城邦过滤：ShouldShowCityState）
   ↓
EquipmentManager.BuyEquipment(side, data)   ← 装备
GridItemManager.BuyToInventory(side, data)  ← 棋盘道具
   ↓
校验：金币是否足够（TrySpendGold）· 背包是否有空位
   ↓
扣款 + 入背包（金币变化触发 OnGoldSettled → UI 刷新）
```

## 4. 数值与公式

### 4.1 价格体系

**所有价格来自配置**，不在代码里：

| 商品 | 价格字段 | 位置 |
|---|---|---|
| 装备 | `EquipmentData.price` | `配置表\装备配置生成器.xlsx` |
| 棋盘道具 | `GridItemData.price` | `Resources/GridItem/*.asset` |
| 拍卖品 | `AuctionItemData.startingPrice` / `minIncrement` | `Resources/Equipment/Auction/` |

### 4.2 ⚠️ 金币供需的粗估（结合《回合与资源》§4.2）

```
一局金币总量（粗估）≈ 440（含开局 50）
装备单价区间（待核）≈ 50~100
→ 一局大约能买 4~8 件装备
```

**但背包只有 5 格**——所以**瓶颈不是钱，是格子**。

> **这个判断很重要**：如果实测发现"钱多得花不完、但格子满了"，那说明**金币的 sink 不足**（钱没有出口）→ 需要考虑增加 sink（如消耗金币的即时效果、道具等），而不是提高装备价格。
>
> **反过来**：如果钱总是不够，说明 `goldPerDamage`（1/点）偏高或装备太贵。

### 4.3 拍卖行的价格上限

拍卖行的成交价**没有上限**（双方竞价抬升）。这意味着：

> 一件起拍 10 的道具，可能被抬到 200——**远超定价商店**。这是贸易城邦的"高风险高投入"特性。**但也可能出现"两人都不敢出价"**的僵局，需 playtest 观察。

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| 金币不足 | 拒绝购买 + **不扣款** | ✓ |
| 背包已满 | ⚠️ 应拒绝购买（5 格上限） | ⚠️ 待确认 |
| 买同一件装备两次 | 允许（多个实例） | ⚠️ 待确认 |
| 非对应城邦的城邦装备 | **不显示**（`ShouldShowEquipment` 过滤） | ✓ |
| 拍卖行：出价低于当前价 + 最小加价 | 应拒绝 | ⚠️ 待确认 |
| 拍卖行：双方都不出价 | 商品流拍（如何处理？） | ⚠️ 待确认 |
| 地下交易未开放时访问 | `IsShopOpen` 返回 false → UI 应隐藏入口 | ✓ |
| 商店在非己方回合 | ⚠️ 是否允许购买（回合限制） | ⚠️ 待确认 |

## 10. 待确认项

1. **没有"刷新库存"机制？** 全项目未搜到 `RefreshStock` 类方法——**商店是否不需要刷新**（固定货架）？还是刷新功能未做？（Roguelike 类游戏通常需要刷新来增加决策）
2. **背包满时的购买保护**：5 格满了还能不能买？如果没拦住会出现"买了但放不下"的状态
3. **拍卖行的完整规则**：竞价流程、结算时机、流拍处理——本文档 §3.4/§4.3 是**基于字段与名词的推断**，未读 `AuctionManager` 全文
4. **地下交易的开放条件**：`ShopOpen` 何时为 true？（城邦 + 回合？+ 其他条件？）
5. **购买是否受回合限制**：只能在己方回合买？（`UI_ShopPanel` 里对 `ActivePlayer` 有引用，推测有约束）
6. **`UndergroundItemData` 的字段**：未读
7. **拍卖行/地下交易的 UI 是否实现**：有 Manager，但 UI 是否接好
8. **金币 sink 是否充足**（§4.2）：**瓶颈是背包格子而非金币**——playtest 时要区分"钱不够"和"没地方放"这两种不同的失衡
