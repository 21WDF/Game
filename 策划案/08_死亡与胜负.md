## 2. 系统概述

### 2.1 目的

回答两个问题：**"这个棋子怎么死？"**、**"什么时候算赢？"**

看起来简单，但它是全项目**最容易出隐蔽 bug**的地方——因为死亡是**多系统交汇点**：伤害结算、被动触发、占据表清理、回合注销、视图销毁、胜负判定，全都在这一刻发生，**顺序错了就会出"半死亡状态"**。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **死得明白** | 死亡有明确的视觉表现（缩小下沉），不是"凭空消失" |
| **有翻盘机会** | 复活类被动能在死亡瞬间介入（哥伦比亚式救援） |
| **胜负即时报** | 最后一个棋子阵亡时立刻结算，不拖沓 |

### 2.3 在整体中的位置

```
伤害结算（HP → 0）
      ↓
死亡流程（本册）— 复活拦截 → 状态清理 → 被动通知 → 视图销毁 → 胜负判定
      ↓
结算面板 · 局外金币结算 · 记录
```

## 3. 核心规则

### 3.1 死亡流程的八个步骤（严格顺序）

`PieceManager.DestroyPiece(model, killer)` 的执行顺序：

| 步 | 动作 | 关键点 |
|---|---|---|
| 0 | **幂等保护** `if (model.IsDestroyed) return` | 防重入（傀儡爆炸可能在伤害链内触发销毁） |
| 1 | **复活介入** `if (TryReviveAlly(model)) return` | ⚠️ **在任何销毁状态变更之前**（见 §3.2） |
| 2 | `model.IsDestroyed = true` | 标记销毁 |
| 3 | `PieceLayoutModel.Remove(model.Coord)` | 移出占据表（该格变为可通行） |
| 4 | `TurnManager.UnregisterPiece(model)` | 从回合系统注销 |
| 5 | **击杀者被动通知** `killer.GetAllPassives() → OnKill(killer, model)` | 纯通知 |
| 6 | **同阵营被动通知** `OnAllyDeath(ally, model)` | ⚠️ **召唤物不算"队友死亡"**（见 §3.3） |
| 7 | **视图延后销毁** `PlayDeath(() => Destroy(viewGo))` | 逻辑已结束，只延后 GameObject（见 §3.4） |
| 8 | `WarCityManager.OnPieceDestroyed(model)` | 战争之城判负钩子（见 §3.5） |

> **顺序即语义**：步骤 2~4 是"逻辑层立即生效"；步骤 7 是"表现层延后"。**这两层绝不能混**。

### 3.2 复活介入：必须在一切之前

```csharp
if (TryReviveAlly(model)) return;   // 步骤 1，在 IsDestroyed = true 之前
```

**为什么必须在最前**（源码注释明确）：

> 复活成功 → **取消销毁整条流程**（棋子原地满状态续命，**不触发 `OnKill` / `OnAllyDeath`**——击杀未成立）。

**关键设计判断**：如果把复活放在中间（比如"先标记销毁、再问复活"），就会出现**"半死亡状态"**——棋子已被移出占据表、回合已注销，但仍活着。这是灾难性的状态不一致。

> **`RevivePassive` 的定位**：框架级的**"取消死亡"拦截**，而不是"死后复活成另一个实体"。它能拦下整条流程。

**与"免死"的口径一致性**：中娅悖论（免死道具）同样**不触发击杀通知**——口径统一为"**没真死就不算击杀**"。

### 3.3 被动通知的两个钩子

| 钩子 | 触发对象 | 说明 |
|---|---|---|
| `OnKill(killer, victim)` | **击杀者**的全部被动 | 击杀奖励类被动（吸血、加钱等） |
| `OnAllyDeath(ally, victim)` | **同阵营存活棋子**的全部被动 | 战旗类被动（队友阵亡加攻等） |

**⚠️ 召唤物不算"队友死亡"**：

```csharp
if (!model.Data.isSummon) { /* 才广播 OnAllyDeath */ }
```

**理由**：傀儡/兔兔伯爵这类召唤物**不算队友**——它们的死亡不应触发"队友阵亡"类被动，否则安柏的傀儡被打死会白送对面触发效果。

> **`victim` 已注销**：`OnAllyDeath` 广播时，victim 已从回合系统注销，所以列表**不含自身**。

### 3.4 逻辑立即 / 视图延后

```csharp
model.IsDestroyed = true;            // ← 逻辑：立即
...
model.View.PlayDeath(() => Destroy(viewGo));   // ← 视图：0.3 秒后销毁
```

**分层的意义**：

| 层 | 时机 | 影响 |
|---|---|---|
| 逻辑层（步骤 2~6） | **立即** | 占据表、回合、被动、胜负判定**全部立刻生效** |
| 表现层（步骤 7） | **延后 0.3 秒** | 棋子播完死亡动作才消失 |

**为什么不延后逻辑**：如果等动画播完才移除占据表，那么在这 0.3 秒内——其他棋子仍认为该格被占据（寻路会绕路）、胜负判定也不会触发。**逻辑等表现 = 状态不一致**。

> **实现细节**：`PlayDeath` 的 `DOScale`/`DOMove` 作用于**动作宿主**（棋子的运行时父节点），`OnComplete` 回调才真正 `Destroy`。这条在《棋子动作》分册（第 5 批）有详述。

### 3.5 胜负判定

| 判定 | 位置 | 说明 |
|---|---|---|
| **常规** | `TurnModel.CheckGameOver()` | 某方棋子全灭 → 对方胜 |
| **幂等** | 已结束直接跳过 | 与 `CheckGameOver` 共用 `IsGameOver` / `OnGameOver` 结束管线 |
| **触发时机** | `TurnManager` 回合流程中 | DoT 致死也走统一入口 → 销毁后由 `CheckGameOver` 判定 |

**事件**：`TurnModel.OnGameOver(PlayerSide winner)` → UI 订阅（`UI_GameOver` / `UI_TurnDisplay` / `UI_BackpackSidebar` 都会响应）。

### 3.6 城邦特殊败北：战争之城

**额外判负条件**：**主将死亡即败**（不论剩余棋子多少）。

| 要点 | 说明 |
|---|---|
| **判定内聚** | `WarCityManager.WarActive`（**静态属性**）—— 非战争城邦下所有方法首行 `if (!WarActive) return` |
| **主将识别** | `_generals.TryGetValue(piece.Owner, out var g) && g == piece` |
| **钩子** | `OnPieceDestroyed(piece)` —— 由 `DestroyPiece` 步骤 8 调用 |
| **调换锁定** | 战争之城有"主将调换"机制，回合开始时解除锁定 |

**⚠️ 一个值得学习的设计**：

> 回合开始的"解除主将调换锁定"在**非战争城邦下也执行**（源码注释："非战争城邦也清，**防残留**"）。

**为什么**：如果只在战争城邦下清理，那么"上一局是战争之城、这一局不是"时，残留的锁定状态会带到新局。**这类"跨局残留"是场景切换类项目的高频 bug**（本项目在 9-13 还修过另外两处同类问题）。

## 4. 数值与公式

### 4.1 死亡表现的时长

| 项 | 值 | 配置字段 |
|---|---|---|
| 死亡动作时长 | **0.3 秒** | `GameConfig.deathDuration` |
| 表现内容 | 缩小到 0.02 + 下沉 0.6（世界单位） | 硬编码幅度 |

**这 0.3 秒就是"逻辑已死、视图未消失"的窗口期**——期间该棋子的 `IsDestroyed` 已为 true，所有系统应据此跳过它。

> ✅ 各系统的守卫：受击表现（`PlayHitReaction`）有 `IsDead || IsDestroyed` 检查；被动遍历普遍有 `IsDead` / `IsDestroyed` 守卫。

### 4.2 复活后的状态

复活成功时棋子"**原地满状态续命**"——恢复多少 HP 取决于 `RevivePassive` 的配置（见 §10）。

## 5. 数据结构（字段定义表）

### 5.1 `PieceModel` 的死亡相关状态

| 字段中文名 | 字段英文名 | 类型 | 说明 |
|---|---|---|---|
| 已死亡 | `IsDead` | bool（派生） | 由 `CurrentHP <= 0` 派生 |
| 已销毁 | `IsDestroyed` | bool | **销毁流程的幂等标志位**，由 `DestroyPiece` 置位 |
| 当前 HP | `CurrentHP` | int | ≤ 0 即死亡 |

> **两个概念要分清**：
> - `IsDead` = "血量归零"（**还没走销毁流程**）
> - `IsDestroyed` = "销毁流程已执行"（占据表已清、回合已注销）
>
> 致命伤害的瞬间 `IsDead` 已为 true 但 `IsDestroyed` 仍为 false——**这个窗口期是很多逻辑的分支点**（例如受击表现会据此跳过，直接进死亡动作）。

### 5.2 `DestroyPiece` 签名与关键调用

| 项 | 内容 |
|---|---|
| 签名 | `void DestroyPiece(PieceModel model, PieceModel killer = null)` |
| 幂等 | `if (model.IsDestroyed) return;` |
| 复活拦截 | `if (TryReviveAlly(model)) return;` |
| 视图销毁 | `model.View.PlayDeath(() => Destroy(viewGo));` |
| 城邦钩子 | `WarCityManager.Instance?.OnPieceDestroyed(model);` |

### 5.3 `WarCityManager` 关键成员

| 成员 | 签名 | 说明 |
|---|---|---|
| **战争之城是否生效** | `static bool WarActive` | 静态属性；全城邦过滤的单一入口 |
| 是否主将 | （表达式）`WarActive && _generals[piece.Owner] == piece` | 主将识别 |
| 调换是否锁定 | `WarActive && piece != null && _swapLocked.Contains(piece)` | 主将调换锁 |
| 棋子销毁钩子 | `void OnPieceDestroyed(PieceModel piece)` | 主将死亡 → 判负 |
| 回合开始清理 | （回合开始时调用） | 解除主将调换锁定（**非战争城邦也清，防残留**） |

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| 同一棋子被重复销毁 | **幂等**（`IsDestroyed` 保护） | ✓ |
| 复活成功 | 取消整条销毁流程，**不触发 OnKill / OnAllyDeath** | ✓ |
| 傀儡在伤害链内被引爆 | 重入时跳过（防 `OnKill` 误触发） | ✓ |
| 召唤物死亡 | **不广播 `OnAllyDeath`** | ✓ |
| 致命伤害瞬间 | `IsDead` = true、`IsDestroyed` = false（窗口期） | ✓ |
| 胜负判定重复触发 | **幂等**（已结束后跳过） | ✓ |
| 非战争城邦下访问战争机制 | 首行 `if (!WarActive) return`（不生效） | ✓ |
| 跨局残留（上局战争 → 本局非战争） | 回合开始清理锁定状态 | ✓ |
| 对局结束瞬间仍有伤害在结算 | ⚠️ 是否有可能"结束后还扣血/发币"？ | ⚠️ 见 §10 |
| 双方同时全灭 | ⚠️ 判定规则未核实（谁赢？平局？） | ⚠️ 见 §10 |
