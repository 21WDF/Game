## 2. 系统概述

### 2.1 目的

回答一个问题：**"这个棋子能走到哪、能打到谁"**——并且让**不同棋子在这件事上手感差异明显**。

这是设计支柱 **P1（空间是资源）** 的直接体现：如果所有棋子移动方式一样、攻击范围都是圆形，那么"站位"就退化成算术题。**范围的可插拔化，是为了让棋子有战术定位**——同一个棋盘上，直线穿透的杜林和环切线的甘雨，走位逻辑完全不同。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **一眼看懂打击面** | 选中棋子时，蓝色（移动）与红色（攻击）高亮清晰呈现该棋子的空间能力 |
| **范围即性格** | 玩家能通过"它怎么走、怎么打"记住棋子（狙击手 = 直线远距，刺客 = 近距环绕） |
| **装备能改空间** | 装备可以加攻击距离/移动距离，范围在高亮上实时体现 |

### 2.3 在整体中的位置

```
棋盘与地图（提供格子集合与距离）
      ↓
范围与空间（本册）— 把"格子集合"翻译成"这个棋子能去哪、能打谁"
      ↓
寻路 · 攻击结算 · 移动动画
```

## 3. 核心规则

### 3.1 三段式可插拔结构（核心设计）

棋子**不直接持有**"能打几格"这一事实，而是持有三个东西：

| 组成 | 字段 | 作用 |
|---|---|---|
| ① **Provider 类型** | `providerClassName`（string） | 决定**形状算法**（直线？圆形？扇形？） |
| ② **构造参数** | `providerJsonParams`（string, JSON） | 填充该形状的**非主范围参数**（如 `{"minRange":2}` / `{"splashRadius":1}` / `{"angle":60}`） |
| ③ **基础范围** | `baseRange`（int） | 主范围数值；**装备加成在此之上叠加** |

运行时由 `RangeProviderFactory` 按类名实例化 Provider，把 `effectiveRange` 传进去算格子：

```
effectiveRange = baseRange + 装备加成(EquipmentMoveRange / EquipmentAttackRange)
```

> **为什么这么设计**：新增一种范围形状**不需要改棋子代码**——写一个 Provider 类、填个类名即可。棋子数据（SO）与算法（代码）解耦，也是"同一套棋子数据能组合出差异很大的空间手感"的实现方式。

### 3.2 Provider 清单

**攻击范围（6 种）**

| Provider 类名 | 形状 | 典型用途 | 已知参数 |
|---|---|---|---|
| `CircleAttackProvider` | 圆形（半径内全部） | 默认近战/常规 | `baseRange` |
| `LineAttackProvider` | 直线 | 穿透型（如杜林） | 待核（见 §5.4） |
| `ConeAttackProvider` | 扇形 | 面向型 | `angle`（示例 60，待核） |
| `MinMaxAttackProvider` | 最小~最大距离环 | 不能打贴身（如狙击） | `minRange`（示例 2，待核） |
| `AreaAttackProvider` | **主目标 + 溅射** | AOE / 溅射伤害 | 见 §3.3（参数最多） |
| `RingTangentProvider` | **环切线 3 格** | 甘雨（决策 D3） | `baseRange` |

**移动范围（5 种）**

| Provider 类名 | 移动方式 | 说明 |
|---|---|---|
| `FreeMoveProvider` | 自由（默认） | 标准 BFS，考虑阻挡 |
| `StraightMoveProvider` | 直线 | 只能沿 6 个方向直走 |
| `FlyMoveProvider` | 飞行 | **无视阻挡**（跨过棋子） |
| `StraightPassProvider` | 直线穿越 | 直线 + 无视阻挡 |
| `ParityMoveProvider` | 奇偶距离 | 只能走到**距离奇偶性匹配**的格子 |

### 3.3 `AreaAttackProvider` 参数（溅射类，参数最全）

| 参数 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `splashRadius` | int | 1 | 溅射半径（0 = 无溅射，退化为单体） |
| `filterByAttackRange` | bool | true | 溅射范围是否裁剪到攻击范围内 |
| `splashIsElemental` | bool | false | 溅射是否带元素（附着 + 触发反应） |
| `splashGoldPercent` | float | 0 | 溅射造成伤害时获得金币的比例 |
| `baseDamage` | int | 0 | 溅射基础伤害（固定部分） |
| `attackPercent` | float | 0 | 溅射按攻击力的百分比 |

> `IsSplash => _splashRadius > 0`：**溅射半径为 0 时该 Provider 退化为普通单体攻击**——这是"一个 Provider 覆盖单体与 AOE 两种表现"的开关。

### 3.4 装备对范围的加成

装备的两个字段会叠加到基础范围上：

| 装备字段 | 作用对象 |
|---|---|
| `bonusAttackRange` | 攻击范围（`attackConfig.baseRange`） |
| `bonusMoveRange` | 移动范围（`moveConfig.baseRange`） |

**叠加后作为 `effectiveRange` 传给 Provider**——Provider 内部**只认传入的范围值**，不关心它是否被装备加成过。

## 4. 数值与公式

### 4.1 范围计算主公式

```
effectiveRange = baseRange + Σ(已装备的 bonusMoveRange 或 bonusAttackRange)

攻击可达格集合 = Provider(className, jsonParams).GetCoords(from, effectiveRange)
```

### 4.2 演算示例

**例 1：默认近战棋子的攻击范围**

```
baseRange = 1（CircleAttackProvider）
未装备加成              → effectiveRange = 1
圆形范围含自身 = 1 + 6 = 7 格
排除自身（不能打自己）   → 6 格可攻击
```

**例 2：装了「探索者护臂」（假设 +1 攻击距离）**

```
effectiveRange = 1 + 1 = 2
圆形范围(半径2) = 1 + 6 + 12 = 19 格
排除自身 → 18 格
```

**例 3：环切线（甘雨 D3）**

```
baseRange = 2（RingTangentProvider）
取"距离 2 的环"上、与目标同环的左右相邻格 → 目标格 + 2 邻居 = 3 格
（不含施法者自身所在环）
```

> **D3 决策的含义**：六边形棋盘上"横向 3 格"没有直觉定义。环切线是唯一几何自洽的解释——**先锁定目标所在的那一圈，再取它左右两格**。

**例 4：直线穿透（杜林，假设 baseRange = 3）**

```
baseRange = 3（LineAttackProvider）
沿朝向的 6 个方向之一，取距离 1、2、3 的格子
→ 3 格，且不因中间有敌人而停止（穿透语义由 Provider 决定）
```

### 4.3 移动范围与攻击范围的算法差异

| | 移动 | 攻击 |
|---|---|---|
| 计算方式 | **BFS**（`ChessBoardModel.GetWalkableCoords`） | **几何取格**（Provider 自算） |
| 是否受阻挡 | ✓ 受影响 | ✗ 不受（攻击范围是空间几何，不管中间有没有人） |
| 是否含起点 | ✗ 不含 | ✓ 含（再由调用方排除自身作为目标） |
| 装备加成字段 | `bonusMoveRange` | `bonusAttackRange` |

> 这个差异很重要：**攻击范围不是"走得到的格子"**，而是几何形状。所以范围高亮（红）不受地形阻挡影响，而移动高亮（蓝）受。

## 5. 数据结构（字段定义表）

### 5.1 `RangeConfig`（PieceData 内嵌类）

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| Provider 类名 | `providerClassName` | string | 决定形状算法 | `CircleAttackProvider` |
| 构造参数 JSON | `providerJsonParams` | string | 非主范围参数；无则留空 | `{"splashRadius":1}` |
| 基础范围 | `baseRange` | int | 主范围数值，装备加成在此叠加 | 1 |

**方法**：`CreateMoveProvider()` / `CreateAttackProvider()` → 内部调 `RangeProviderFactory`

### 5.2 `PieceData` 范围相关字段

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| 移动范围配置 | `moveConfig` | RangeConfig | 默认 `FreeMoveProvider` / range 3 | — |
| 攻击范围配置 | `attackConfig` | RangeConfig | 默认 `CircleAttackProvider` / range 1 | — |

> **决策 D5**：范围配置**内联在 PieceData 里**，不单独做 SO 资产层。理由：避免每个棋子产生 2 个额外资产（10 棋子 = 20 个资产），且范围与棋子是强绑定关系，拆开反而难维护。

### 5.3 `IAttackRangeProvider` / `IMoveRangeProvider`（接口）

| 接口 | 方法签名 | 职责 |
|---|---|---|
| `IAttackRangeProvider` | `List<HexCoord> GetAttackZone(HexCoord from, int effectiveRange, HexCoord? target, ChessBoardModel model)` | 计算攻击作用格集合 |
| `IMoveRangeProvider` | （返回可移动坐标集合；具体签名待核） | 计算可移动格集合 |

**⚠️ 攻击 Provider 的两阶段语义**（以 `RingTangentProvider` 实现为例）：

| 阶段 | `target` 取值 | 返回内容 |
|---|---|---|
| **高亮阶段**（选中棋子、尚未点目标） | `null` | `effectiveRange` 半径内的**可选目标位**（**不含施法者自身**） |
| **执行阶段**（已点定目标） | 具体坐标 | **实际作用格集合**（环切线 = 目标格 + 同环左右 2 邻居；棋盘外的邻居剔除） |

> **为什么需要两阶段**：高亮时玩家还没决定打哪，只能显示"哪些格子能作为目标"；点定之后，才能算出"这一击实际覆盖哪些格"。**同一个 Provider 必须能同时回答这两个问题**——这是攻击范围 Provider 接口设计的关键。

> **环切线的几何判定**（源码注释特别强调）：同环邻居 = `target` 的 6 个邻居中、**到 `from` 的距离仍等于 `d = Distance(from, target)`** 的那 2 个。**必须用 `HexCoord.Distance` 判定，不能用"是否相邻"，也不能用"到 target 的距离"**——这两个替代写法都会算出错误结果。

**实现类**：见 §3.2 的 11 个 Provider。

### 5.4 各 Provider 的构造参数（✅ 已核实）

**参数类只有 3 个**（`MinMaxParams` / `ConeParams` 定义在 `RangeProviderFactory.cs` 内，`AreaSplashParams` 定义在 Provider 自身文件内），**其余 Provider 无构造参数**：

| Provider | 参数类 | 参数字段 | 默认值 |
|---|---|---|---|
| `MinMaxAttackProvider` | `MinMaxParams` | `minRange` / `maxRange` | `0` / `0` |
| `ConeAttackProvider` | `ConeParams` | `angle` / `length` | `60` / `0` |
| `AreaAttackProvider` | `AreaSplashParams` | `splashRadius` / `filterByAttackRange` / `splashIsElemental` / `splashGoldPercent` / `baseDamage` / `attackPercent` | `1` / `true` / `false` / `0` / `0` / `0` |
| `CircleAttackProvider` | **无** | — | — |
| `LineAttackProvider` | **无** | — | — |
| `RingTangentProvider` | **无**（源码注释明确"无构造参数"） | — | — |
| `FreeMoveProvider` · `StraightMoveProvider` · `FlyMoveProvider` · `StraightPassProvider` · `ParityMoveProvider` | **无** | — | — |

> **只有 3 种 Provider 需要填 `providerJsonParams`**（MinMax / Cone / Area），其余留空即可。
> 形状本身由几何算法决定：比如 `RingTangentProvider` **不需要参数**——它的 `baseRange` 就是环的半径，形状（目标格 + 同环左右 2 邻居）是算法算出来的。

## 6. 配置方式

| 配置项 | 位置 |
|---|---|
| 棋子范围 | `PieceData.asset` → `moveConfig` / `attackConfig`（Inspector 直接填） |
| Provider 实现 | `Assets/Game/Piece/Range/{Move,Attack}/*.cs` |
| 工厂 | `Assets/Game/Piece/Range/RangeProviderFactory.cs` |
| 装备加成 | `EquipmentData.bonusMoveRange` / `bonusAttackRange` |

**新增一种范围形状的步骤**：
1. 在 `Range/Move/` 或 `Range/Attack/` 新建类，实现对应接口
2. 在 `RangeProviderFactory` 里注册类名映射
3. 在棋子的 `RangeConfig.providerClassName` 填类名
4. 如需参数，填 `providerJsonParams`（JSON）

**不需要改动**：棋子逻辑、棋盘、UI——范围是纯数据 + 工厂实例化。

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| `providerClassName` 填了不存在的类名 | 工厂返回 null / 报错（**不应静默**） | ⚠️ 待确认 |
| `providerJsonParams` 是非法 JSON | 待确认（应报错而非静默用默认值） | ⚠️ 待确认 |
| `baseRange = 0` | 攻击范围退化为仅自身（无可攻击目标） | ⚠️ 待确认 |
| 装备把范围加成到很大 | 范围计算正常，但高亮性能需注意 | ⚠️ 待确认 |
| 溅射半径 > 攻击范围 | `filterByAttackRange = true` 时被裁剪 | ✓ 有参数控制 |
| 飞行单位穿过棋子 | 允许（FlyMove 语义） | ✓ |

> **前三项是真实风险**：Provider 类名与 JSON 参数都是**字符串配置**，填错时如果工厂静默返回 null，会表现为"棋子不能动也不能打"——这类问题排查成本很高。建议在工厂里对**类名找不到**和 **JSON 解析失败**显式报警。
