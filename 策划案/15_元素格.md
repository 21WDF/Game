## 2. 系统概述

### 2.1 目的

让**棋盘本身参与战斗**。

这是设计支柱 **P1「空间是资源」** 的又一层落地——元素格把"地盘"变成有代价的地形：踩上去会持续掉血、攻击距离变短、移动变慢。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **地形有代价** | 站在元素格上的棋子持续受损或减益 → "站哪"变成需要权衡的决策 |
| **可持续影响战局** | 元素格持续若干回合，不是一次性效果 |
| **可被感知** | 格子有明确的材质表现（火/雷/水/冰各一种颜色） |

### 2.3 在整体中的位置

```
大招（声明作用范围 IUltimateAreaProvider）
      ↓
元素格（本册）— 把范围转化为持续地形效果
      ↓
回合结算（持续伤害 + 减益）· 伤害跳字 · 元素附着
```

## 3. 核心规则

### 3.1 元素格的生命周期

```
大招释放（enableElementTiles = true）
      ↓
效果类声明作用范围（IUltimateAreaProvider.GetUltimateArea）
      ↓
ElementTileManager.ApplyElementTiles(coords, element, durationTurns)
      ↓
【持续 durationTurns 个回合】每回合结束结算（OnTurnEnded）
      ↓
回合数耗尽 → 格子恢复
```

**关键设计**：大招**只声明范围**，替换由 `ElementTileManager` **统一完成**——各大招不各写一套替换逻辑。

### 3.2 生成入口（大招侧）

| 配置 | 位置 | 说明 |
|---|---|---|
| `enableElementTiles` | `PieceData.UltimateConfig` | 勾选后大招释放时生成元素格 |
| `elementTileDurationTurns` | 同上 | 元素格持续回合数（默认 **4**） |
| 作用范围 | 效果类实现的 `IUltimateAreaProvider` | **只声明几何范围**（不区分效果性质、不排除被占据的格子） |

**⚠️ 缺一不可**：若勾选了 `enableElementTiles` 但效果类**未实现 `IUltimateAreaProvider`** → **不产生任何替换** + **告警一次**（提示适配缺失）。**这不是静默失效**。

**当前启用元素格的大招**（从棋子资产读得）：菲林斯（雷扫）· 杜林（贯日炎枪）· 克洛琳德（雷驰突进）· 甘雨（霜华贯矢）· 雷电将军（无想一刀）

### 3.3 回合结算

`ElementTileManager.OnTurnEnded()` 在回合结束时：

1. **持续伤害**：站在元素格上的棋子受到伤害 → 走 `ApplyIncomingDamage(..., DamageSource.Dot, DamageKind.True, ...)`
   - **`DamageKind.True`（真实伤害）** → **无视防御与护盾**
   - **`DamageSource.Dot`** → 受击表现为**轻量**（仅脉冲，无位移）
2. **减益查询**：`GetAttackRangeDebuff(piece)` / `GetMoveRangeDebuff(piece)` 供范围计算时调用
3. **回合数递减**：`turnsRemaining--`，归零则移除

> **两条设计判断值得注意**：
> - **环境伤害用真实伤害**（无视防御）——保证"站在火里就是会掉血"，不会被高防单位豁免
> - **受击用轻量表现**——避免每回合全场棋子抖动（见《棋子表现》§3.5）

### 3.4 四元素格的差异

每个元素格条目有**三个效果参数**（另有材质）：

| 参数 | 作用 |
|---|---|
| `damagePerTurn` | 每回合对停留棋子的环境伤害 |
| `attackRangeDebuff` | 攻击距离减益 |
| `moveRangeDebuff` | 移动距离减益 |

**设计意图**（从参数组合推断）：不同元素格**惩罚的维度不同**——有的扣血、有的减攻距、有的减移距。这让"踩哪种格子"成为不同的取舍。

> ⚠️ **各元素格的实际参数值需从资产读**（见 §10）。

### 3.5 ⭐ 雷电残留：跨城邦的变体

`ElementTileManager` 同时承载**元素城邦**（元素格）与**季风城邦**（雷电残留）两种格子状态：

| 特性 | 元素格 | 雷电残留 |
|---|---|---|
| 归属城邦 | **元素** | **季风** |
| 标记 | — | `isLightning = true` |
| 强度 | 固定（配置） | **`strength` 可变，由 `MonsoonManager` 衰减** |
| 材质 | 元素色 | `lightningResidueMaterial` |

**这是一个值得注意的设计**：**同一个 Manager 服务两个城邦**——把"格子上的持续状态"抽象成一个通用载体，元素格与雷电残留只是它的两种变体。

> **为什么这么做**：两者在机制上高度相似（都是"站在格子上持续受损 + 有回合数"），共用一套状态管理能避免重复实现。**但要注意城邦过滤**：元素格的生成受 `ElementSystemActive` 约束，雷电残留受 `MonsoonActive` 约束。

## 4. 数值与公式

### 4.1 `ElementTileConfig` 顶层参数

| 参数 | 代码默认 | 说明 |
|---|---|---|
| `defaultDurationTurns` | **4** | 元素格默认持续回合数 |
| `defaultAttachGauge` | **1** | 每次附着的元素量 |

### 4.2 各元素格条目

结构：每个元素（火/雷/水/冰）一个条目，含 `damagePerTurn` / `attackRangeDebuff` / `moveRangeDebuff` / `material`。

**代码默认值**：三个数值参数**均为 0**（即默认不产生任何效果）——**实际值在 `ElementTileConfig.asset`**。

> ⚠️ **关于配置表的一处自查**：我在 `全局参数配置表.xlsx` 的 `ElementTile` sheet 里填的是**推断值**（如"火 2 伤害 / 水 减攻 1 / 冰 减移 1"）——**那是从设计意图推断的，不是从资产读的**。**请以 `ElementTileConfig.asset` 的实际值为准**，该 sheet 需要按资产校正（见 §10 第 1 条）。

### 4.3 环境伤害的性质

```
伤害来源：DamageSource.Dot      → 受击表现：轻量（仅脉冲）
伤害类型：DamageKind.True       → 无视防御与护盾
元素附着：ElementType.None      → 不附着元素、不触发反应
```

> **"不附着元素"是刻意的**（决策 D6 的例外清单）：元素格是**环境效应**，不是"角色主动直接伤害"——如果它会附着元素，站在火格上就会不断与自己的附着反应，规则会失控。

### 4.4 持续伤害的数量级（演算）

```
假设某元素格 damagePerTurn = 2、持续 4 回合：
单个棋子全程停留 = 2 × 4 = 8 点伤害
```

**对比**：棋子 HP 在 80~120 之间、单次普攻约 15~25 点。

> **结论**：元素格的伤害是**持续性的小额消耗**，不是决定性威胁。它的价值在于**迫使对手移动**（占用 AP）而不在于直接击杀——这正是 P1"空间是资源"的表达。

## 10. 待确认项

1. **⚠️ 各元素格的实际参数值**：文档 §4.2 列的"代码默认 0"未必等于资产实际值——**需读 `ElementTileConfig.asset`**。**同时我在 `全局参数配置表.xlsx` 的 `ElementTile` sheet 里填的是推断值（火 2 伤害等），需要按资产校正**（这是我这边的待办，已记入 00 汇总）
2. **元素格与雷电残留能否叠加在同一格**：两套状态共用一个 Manager，但**一格是否能同时是元素格与雷电残留**未确认
3. **回合数是否对玩家可见**：格子上剩几回合，目前是否有 UI/视觉提示
4. **减益是否对玩家可见**：站在格子上时，"攻击距离 -1"是否被明确告知（对应 P3 信息透明）
5. **元素格的伤害是否随强度变化**：雷电残留有 `strength`（可衰减），普通元素格是固定的 `damagePerTurn`——设计上是否有意区分
6. **元素格对召唤物是否生效**：兔兔伯爵（9999 HP）站在元素格上是否同样受伤
7. **元素格的重叠覆盖**：同一格被两次大招覆盖时（不同元素），是覆盖还是叠加
