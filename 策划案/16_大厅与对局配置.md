## 2. 系统概述

### 2.1 目的

给游戏一个**体面的入口**，并把"开局前的配置"收在一处。

回答的问题：**"这局怎么玩"**——棋盘多大、每方几个棋子、要不要城邦。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **开局前可商量** | 热座两人在开始前就能定规则（棋盘大小 / 棋子数 / 城邦），而不是进游戏才发现不合适 |
| **打开就能玩** | 首次启动自动登录测试账号，**不被登录界面卡住** |
| **调试不受阻** | 开发时可直接打开局内场景 Play，跳过整个大厅 |

### 2.3 在整体中的位置

```
大厅（本册）— 开局前配置
      ↓ 跨场景传递（SessionConfig）
局内：选棋子 → 部署 → 对战 → 结算
      ↓
返回大厅（可重开一局）
```

## 3. 核心规则

### 3.1 场景结构

| 场景 | Build index | 作用 |
|---|---|---|
| `MainMenu.unity` | **0**（首位） | 大厅：正式入口 |
| `SampleScene.unity` | 1 | 局内：一局对战 |

### 3.2 大厅内容

| 区域 | 组件 | 说明 |
|---|---|---|
| **对局配置** | `UI_MainMenu` | 三项：棋盘大小 / 每方棋子数 / 城邦模式 |
| **城邦排除区** | `UI_CityStateExclusion` | 双方各排除 2 个城邦（见《城邦系统》） |
| 账号与金币显示 | `UI_MainMenu` | 当前账号、局外金币余额 |
| 登录面板 | `UI_LoginPanel` | 账号切换 / 注册（见《玩家档案》） |
| 棋子商店 | `UI_PieceShopPanel` | 用局外金币购买棋子（见《局外金币经济》） |
| 开始 / 退出 | `UI_MainMenu` | 「开始游戏」在双方城邦选完后才可用 |

### 3.3 ⭐ 三项对局配置

| 配置项 | 可选值 | 默认 | 影响 |
|---|---|---|---|
| **棋盘大小** | 半径 **4 / 5 / 6**（61 / 91 / 127 格） | 4 | 空间规模与对局时长 |
| **每方棋子数** | **3 / 5 / 7** | 7 | 对局规模；**受棋池解锁限制**（见《局外金币经济》） |
| **城邦模式** | **随机城邦 / 无城邦** | 随机城邦 | 是否启用城邦机制 |

### 3.4 ⭐ 跨场景传递：`SessionConfig`

大厅与局内是**两个场景**，配置通过**静态类** `SessionConfig` 传递：

| 字段 | 类型 | 说明 |
|---|---|---|
| `BoardRadius` | int | 棋盘半径 |
| `PiecesPerSide` | int | 每方棋子数 |
| `CityStateMode` | bool | 是否有城邦 |
| `ResolvedCityState` | CityStateKind | **大厅结算出的城邦** |
| `CityStateResolved` | bool | 是否已结算（**区分「大厅配置过」与「开发直进」**） |
| `IsConfigured` | bool | 是否经过大厅配置 |
| `AllowedBoardRadii` / `AllowedPiecesPerSide` | int[] | 合法选项集 |

**设计要点**：

| 要点 | 说明 |
|---|---|
| **唯一写入口** `Apply(...)` | 属性带 `private set`，外部无法直接写 |
| **越界值收敛** | `ClampToOption` 把非法值收敛到最近的合法选项 |
| **不碰 `GameConfig`** | 避免污染全局平衡参数 + 避免 Editor 把运行期修改持久化写回资产 |
| **跨场景存活** | 静态字段天然跨场景（也是"配置传入局内"的载体） |

### 3.5 ⭐ 开发直进通道

**直接打开 `SampleScene` 按 Play 也能正常开局**：

```
SessionConfig.IsConfigured == false
  → 棋盘半径回退 GameConfig.initialRadius
  → 本局城邦 = None（机制全关）
  → 正常进入选棋子
```

> **为什么保留这个通道**：开发调试时不该每次都过大堂。代价是**需要所有配置读取点都能处理"未配置"的情况**（用 `IsConfigured` 判断回退）。

### 3.6 「开始游戏」的语义

| 层面 | 含义 |
|---|---|
| **本地模式** | 双方都完成城邦选择后解锁 → 点击 = 结算城邦 + 载入局内 |
| **联机预留** | = **本地玩家的"准备 / 提交"信号**（"我选完了，等对方"）|

**门控实现**：`UI_MainMenu` 查 `CityStateManager.HasBothSubmitted`（**不持有本地布尔**）——见《城邦系统》§5.3。

## 4. 数值与公式

### 4.1 棋盘规模的换算

```
半径 r → 格数 = 3r(r+1) + 1
  4 → 61
  5 → 91
  6 → 127
```

> **对时长的影响（[PLACEHOLDER]）**：棋盘越大，双方接触所需回合越多 → 单局更长。若实测"半径 6 太拖"，可考虑在 UI 上标注推荐时长。

### 4.2 每方棋子数与棋池解锁

| 拥有棋子数 | 可选的每方棋子数 |
|---|---|
| 4（初始） | 仅 **3** |
| 5 | 3 · 5 |
| 7+ | 3 · 5 · 7 |

**解锁判据**：`拥有数 ≥ 选项值`（"池子要装得下要选的数"）。
**默认值钳制**：若 `PiecesPerSide` 记录的值当前未解锁（如删档后），**回退到最大可用值**（共三处防御：大厅回显、开始前、选棋子界面）。

## 5. 数据结构（字段定义表）

### 5.1 `SessionConfig`（静态类，`Core/`）

| 成员 | 类型 | 说明 |
|---|---|---|
| `DefaultBoardRadius` / `DefaultPiecesPerSide` / `DefaultCityStateMode` | const | **默认值 = 现状**（4 / 7 / true） |
| `AllowedBoardRadii` | `int[]` | `{4, 5, 6}` |
| `AllowedPiecesPerSide` | `int[]` | `{3, 5, 7}` |
| `BoardRadius` / `PiecesPerSide` / `CityStateMode` | 属性（private set） | 当前值 |
| `ResolvedCityState` / `CityStateResolved` | 属性（private set） | 城邦结算结果 |
| `IsConfigured` | 属性（private set） | 是否经大厅配置 |
| `Apply(boardRadius, piecesPerSide, cityStateMode)` | 方法 | **唯一写入入口** |
| `ApplyCityState(kind)` | 方法 | 写入城邦结算结果 |
| `ResetCityStateSelection()` | 方法 | 清空城邦选择（**消费即清**） |

### 5.2 `UI_MainMenu` 关键字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `registry` | `PieceRegistry` | **棋池解析源（必须拖）** |
| `startButton` / `exitButton` | Button | |
| `switchAccountButton` / `shopButton` | Button | 打开登录 / 商店面板 |
| `accountText` / `goldText` | TMP | 账号与金币显示 |
| `boardSizeButtons` / `piecesButtons` / `cityStateButtons` | Button[] | 三组选项按钮 |
| `cityStateExclusionPanel` | `UI_CityStateExclusion` | 城邦排除区引用 |
| `loginPanel` / `shopPanel` | UI 面板 | |
| `gameSceneName` | string | 局内场景名（默认 `SampleScene`） |

### 5.3 `LobbyUI_SetupTool`（Editor 工具）

| 项 | 说明 |
|---|---|
| 菜单 | `Tools > Chess > 搭建大厅 UI` |
| 作用 | **一键创建/补齐大厅 UI 对象并自动接好全部引用** |
| 特性 | **幂等**（只补缺的）· **零销毁操作**（不会误删既有对象）· 经 **Unity API** 创建（**无需"复制触发导入"**） |
| 附带 | 缺失时自动补 `EventSystem` |

> **这个工具的存在意义**：大厅 UI 有几十个对象与引用，手工搭一次成本很高且易漏。工具把它变成"点一下菜单"。
