## 2. 系统概述

### 2.1 目的

让每一次伤害**都能被"读到"**。

这是设计支柱 **P3「信息透明」** 的落地：玩家不看面板，也能从跳字读出**四个信息**——打了多少、什么元素、什么性质、是否触发反应。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **数字即反馈** | 每次伤害都有数字，且位置在受击者身上（能看出打的是谁） |
| **一眼读出元素** | 颜色直接对应元素（火橙红 / 水蓝 / 雷金 / 冰浅蓝） |
| **一眼读出性质** | 形状对应伤害类型（纯色块 / 渐变 / 描边） |
| **反应有强调** | 触发反应时独立提示（如"蒸发"），与伤害数字区分 |

### 2.3 在整体中的位置

```
伤害结算（数字 + 类型 + 元素 + 反应）
      ↓
跳字系统（本册）— 把数字变成可读的视觉
      ↓
FloatingTextPool（对象池）· TMP（颜色/渐变/描边）
```

## 3. 核心规则

### 3.1 ⭐ 两个正交维度（本系统的核心设计）

**跳字的颜色与形态表达的是两件不同的事**：

| 维度 | 表达 | 取值来源 |
|---|---|---|
| **颜色** | **元素类型** | `ElementColorMapper.GetElementDamageColor(element)` |
| **形态** | **伤害类型**（物理/魔法/真实） | `FloatStyleKind` |

> **源码注释明确**："跳字形态（View 层）——**与颜色正交**"。
>
> **这条设计的价值**：一个跳字同时承载两个信息（是什么元素 + 什么性质），信息密度高，且两个维度**互不干扰**——不需要为"物理火伤"这种组合专门设计一种颜色。

### 3.2 颜色规则（= 元素）

| 元素 | 颜色 | 配置字段 |
|---|---|---|
| 火 | 橙红 | `floatDamageFire` |
| 水 | 蓝 | `floatDamageWater` |
| 雷 | 金 | `floatDamageThunder` |
| 冰 | 浅蓝 | `floatDamageIce` |

**无元素时**（按伤害类型取色）：

| 伤害类型 | 颜色 | 配置字段 |
|---|---|---|
| 物理 | **白** | `floatDamagePhysical` |
| 魔法 | **紫** | `floatDamageMagical` |
| 真实 | **金** | `floatDamageTrue` |

**反应提示色**（7 个独立字段）：`floatReactionDamage`（通用）+ `floatReactionVaporize` / `Melt` / `Overload` / `Electro` / `Frozen` / `Superconduct`（六种反应各一色）。

### 3.3 形态规则（= 伤害类型）

| `FloatStyleKind` | 形态 | 默认用于 | 实现手段 |
|---|---|---|---|
| **`Plain`** | 纯色块 | **物理伤害** | TMP 直接着色 |
| **`Gradient`** | 上下明暗渐变 | **魔法伤害** | TMP 顶点渐变（上端提亮 / 下端压暗） |
| **`Outline`** | 深色描边 | **真实伤害** | TMP UNDERLAY（SDF 膨胀一层深色底，文字本体保持原色） |

**⚠️ 非伤害跳字的形态固定为 `Plain`**（源码注释明确）：回血 / 护甲 / 反应提示等**一律纯色**，不参与形态维度。

> **这条约束很重要**：形态是**伤害类型专属**的表达方式。如果给回血也加渐变，形态维度就失去了"读伤害性质"的意义。

### 3.4 跳字类型清单

| 类型 | 颜色 | 形态 | 特殊 |
|---|---|---|---|
| **伤害（物理）** | 元素色 / 白 | `Plain` | — |
| **伤害（魔法）** | 元素色 / 紫 | `Gradient` | — |
| **伤害（真实）** | 元素色 / 金 | `Outline` | — |
| **反应提示** | 独立紫色 | `Plain` | 文本如"蒸发！×2" |
| **回血** | 绿（`FloatStyles.HealColor`） | `Plain` | — |
| **护甲** | 蓝（`FloatStyles.ArmorColor`） | `Plain` | — |
| **暴击** | 金（`FloatStyles.CritColor`） | `Plain` | **带抖动**（`shake = true`） |

### 3.5 对象池

`FloatingTextPool` 采用**对象池**模式——跳字对象复用，避免每次伤害都 `Instantiate`/`Destroy`（战斗中跳字频率极高）。

## 4. 数值与公式

### 4.1 动画参数（`GameConfig`「浮动文字动画参数」区块，16 个字段）

**每类跳字三件套**：时长 / 上漂距离 / 字号。

| 跳字类型 | 时长（秒） | 上漂距离 | 字号 |
|---|---|---|---|
| 物理 / 元素伤害 | `floatDurationPhysical` = **0.8** | `floatDistancePhysical` = **1.5** | `floatFontSizePhysical` = **10** |
| 反应提示 | `floatDurationReaction` = **1.0** | `floatDistanceReaction` = **2.0** | `floatFontSizeReaction` = **12** |
| 回血 | `floatDurationHeal` = **0.6** | `floatDistanceHeal` = **0.8** | `floatFontSizeHeal` = **9** |
| 护甲 | `floatDurationArmor` = **0.8** | `floatDistanceArmor` = **0.8** | `floatFontSizeArmor` = **8** |
| 暴击 | `floatDurationCrit` = **1.0** | `floatDistanceCrit` = **2.5** | `floatFontSizeCrit` = **16** |

**全局**：`floatAlphaFadeStart` = **0.5**（Alpha 开始衰减的时间比例；0 = 立即衰减，1 = 全程不衰减）

### 4.2 字号层级（设计意图推断）

```
暴击 16 > 反应 12 > 伤害 10 > 回血 9 > 护甲 8
```

**排序逻辑**：**越"值得注意"的事件字号越大**——暴击最大（情绪高点）、护甲最小（重复性最高的反馈）。

> **这个梯度是有设计的**：如果所有跳字字号相同，玩家会因为视觉噪音而**忽略掉重要的那一个**。

### 4.3 上漂距离的层级

```
暴击 2.5 > 反应 2.0 > 伤害 1.5 > 回血 0.8 = 护甲 0.8
```

同样遵循"重要的事件飘得更高"——**用位移拉开空间层次**，避免多个跳字挤在一起互相遮挡。

## 5. 数据结构（字段定义表）

### 5.1 `FloatStyleKind`（形态枚举）

| 值 | 含义 | 实现 |
|---|---|---|
| `Plain` | 纯色（TMP 直接着色） | — |
| `Gradient` | 渐变（TMP 顶点渐变：上端提亮 / 下端压暗） | — |
| `Outline` | 描边（TMP UNDERLAY：SDF 膨胀一层深色底，文字本体保持原色） | — |

### 5.2 `FloatStyle`（跳字样式参数，`[System.Serializable]` struct）

| 字段中文名 | 字段英文名 | 类型 | 注释 |
|---|---|---|---|
| 文字颜色 | `color` | Color | 元素色或伤害类型色（由 `ElementColorMapper` 取得） |
| 总时长 | `duration` | float | 上漂 + 淡出总时长（秒） |
| 上漂距离 | `floatDistance` | float | 世界单位 |
| 字号 | `fontSize` | float | TMP fontSize |
| 是否抖动 | `shake` | bool | **暴击用** |
| 跳字形态 | `kind` | FloatStyleKind | 物理=纯色 / 魔法=渐变 / 真实=描边；默认纯色 |

**构造**：`FloatStyle(color, duration, floatDistance, fontSize, shake, kind = Plain)`

### 5.3 `FloatStyles`（静态预设库）

| 成员 | 说明 |
|---|---|
| `ReactionColor` | 反应提示色 `(0.8, 0.4, 1)` 紫 |
| `HealColor` | 回血色 `(0.3, 1, 0.3)` 绿 |
| `ArmorColor` | 护甲色 `(0.3, 0.5, 1)` 蓝 |
| `CritColor` | 暴击色 `(1, 0.85, 0.2)` 金 |

> ⚠️ 源码注释："**本阶段不暴露到 Inspector**：由 `FloatStyles` 静态预设库提供实例，**后续可收进 `GameConfig`**"。
> 但 `GameConfig` 里**已有** 16 个动画参数 → 说明**部分已收进**。二者的分工需确认（见 §10）。

### 5.4 `ElementColorMapper`（元素色映射）

| 方法 | 签名 | 说明 |
|---|---|---|
| 取元素伤害色 | `Color GetElementDamageColor(ElementType element)` | 用默认配置 |
| 取元素伤害色（带配置） | `Color GetElementDamageColor(ElementType element, GameConfig config)` | 从 `GameConfig` 读取 |
| 兜底 | 默认返回 `(0.8, 0.4, 1)` 紫 | 配置为空时 |

> **元素光环也复用这个映射**（见《棋子表现》）——**元素色只有一处定义**，跳字与光环不会出现色差。

### 5.5 `FloatingText` / `FloatingTextPool`

| 类 | 职责 |
|---|---|
| `FloatingTextPool`（MonoBehaviour） | 对象池：提供/回收跳字实例 |
| `FloatingText`（MonoBehaviour） | 单个跳字的播放（颜色/渐变/描边/上漂/淡出/抖动） |

**`FloatingText` 内部持有的样式常量**：`OutlineBaseColor` = `(0.05, 0.05, 0.05, 1)`（描边基色，近黑）。

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| 配置为空 | `ElementColorMapper` 返回兜底紫 `(0.8, 0.4, 1)` | ✓ |
| 无元素伤害 | 按伤害类型取色（物理白 / 魔法紫 / 真实金） | ✓ |
| 非伤害跳字 | 形态固定 `Plain`（不参与形态维度） | ✓ |
| 跳字过多（AOE 多目标） | 对象池复用，避免频繁 `Instantiate`/`Destroy` | ✓ |
| 短时间多段伤害 | 跳字会各自独立上漂（可能重叠） | ⚠️ 见 §10 |
| 世界坐标 → 屏幕位置 | 跟随受击者（跳字位置由调用方给） | ✓ |
| `floatAlphaFadeStart` 边界 | 0 = 立即衰减，1 = 全程不衰减 | ✓ |

## 10. 待确认项

1. **⚠️ 记忆与代码不符已更正**：项目记忆曾记"物理红 / 魔法紫 / 真实白"，**实际代码是物理白 / 魔法紫 / 真实金**（`GameConfig.floatDamagePhysical = Color.white`、`floatDamageTrue = (1, 0.85, 0.3)`）——**以代码为准**，已更正记忆
2. **`FloatStyles` 与 `GameConfig` 的分工**：源码注释说"后续可收进 `GameConfig`"，而 `GameConfig` 已有 16 个动画参数 → **但 4 个非伤害样式色（反应/回血/护甲/暴击）仍在 `FloatStyles` 代码里**。是否要一并收进配置？调这两个色目前需要改代码
3. **跳字重叠**：AOE 多目标或同一目标多段伤害时，多个跳字可能重叠遮挡——是否有错位/合并机制
4. **描边宽度**：`Outline` 形态的描边粗细是否可调（当前 `OutlineBaseColor` 是常量，宽度未见表露）
5. **跳字的伤害数值与面板一致性**：跳字显示的是实际伤害还是原始值（应与结算一致）
6. **暴击的触发条件**：游戏里"暴击"目前是否真的会触发（是否有暴击机制）
7. **元素反应跳字与伤害跳字的共存**：触发反应时是否同时显示"反应名"与"伤害数字"（两个跳字的相对位置如何）
