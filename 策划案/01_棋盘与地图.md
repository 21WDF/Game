## 2. 系统概述

### 2.1 目的

棋盘是**空间资源**的载体。它回答一个问题：**"这一步能走到哪、能打到谁、值不值得花道具改造地形"**。

它不是一张固定的背景图——**玩家可以用道具实时增删格子**，这是本项目四条设计支柱中 P1（空间是资源）的落地实现。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **一眼看懂空间** | 移动范围（蓝）/ 攻击范围（红）高亮清晰，落点可预览 |
| **改造是决策而非操作** | 扩展石能拉出通路、删除石能切断敌人退路——同一道具在不同局面价值不同 |
| **误操作可撤销** | 攻击前可查看路径；未确认的移动不消耗资源 |

### 2.3 在整体中的位置

```
棋盘与地图（本册）
   ├─ 为 范围与空间 提供"格子集合"与"距离"
   ├─ 为 寻路 提供"可达性"与"阻挡谓词"
   ├─ 为 棋子部署 提供"可放置区域"
   └─ 被 棋盘道具 改造（增删格）
```

## 3. 核心规则

### 3.1 坐标系统

采用**轴向坐标（axial coordinates）**，两个整数定位一个六边形格子：

| 字段 | 含义 | 备注 |
|---|---|---|
| `q` | 列 | 轴向坐标横轴 |
| `r` | 行 | 轴向坐标纵轴 |

- **邻居**：每格 6 个邻居，按 `directionIndex` 0~5 索引（`HexCoord.Neighbor(i)`）
- **距离**：`HexCoord.Distance(other)` —— 六边形曼哈顿距离（用于攻击范围判定）
- **格子集合**：以 `radius` 生成——`HexCoord.AllCoordsInRadius(radius)`

> **为什么用轴向坐标**：六边形没有直觉的"上下左右"，轴向坐标是唯一能用两个整数无损表达六边形网格的方案，且距离计算无需开方。

### 3.2 棋盘生成与规模

| 半径 | 格子数 | 说明 |
|---|---|---|
| **4** | **61** | 默认（`GameConfig.initialRadius = 4`） |
| 5 | 91 | 可在大厅配置 |
| 6 | 127 | 可在大厅配置 |

**生成规则**：以原点为中心，取所有到原点距离 ≤ radius 的格子。

**配置入口**：大厅「棋盘大小」选项（`SessionConfig.BoardRadius`，可选 4/5/6）。
**开发直进时**：未经过大厅（`SessionConfig.IsConfigured == false`）→ 回退 `GameConfig.initialRadius`。

### 3.3 单格增删（棋盘改造）

棋盘**不是生成后就固定**的。两个原子操作支撑所有改造：

| 操作 | 语义 | 约束 |
|---|---|---|
| **AddCoord** | 在指定坐标新增一格 | 已存在则忽略（幂等） |
| **RemoveCoord** | 移除指定坐标的格子 | 不存在则忽略（幂等） |

**半径语义**：`Radius` 是**记录值**，不随单格增删自动变化——`SetRadius` 仅在棋盘**整体扩展**时由外部显式调用。**单格增删不改变整体半径语义**。

> 这条很重要：如果单格增删顺手改半径，会导致"半径 4 的棋盘加一格后变成半径 5 的语义"，范围与生成逻辑会全部错位。

### 3.4 棋盘道具（改造手段）

三种道具，效果由**独立的 Effect 类**实现（可插拔）：

| 道具 | 效果类 | 作用 | 关键参数 |
|---|---|---|---|
| **扩展石** | `ExpandTileEffect` | 在目标坐标新增一格 | 须邻接既有棋盘（保证连通性） |
| **删除石** | `RemoveTileEffect` | 移除目标坐标的格子 | `minTilesAfter = 7`（删后剩余格数下限，防止把棋盘删空） |
| **传送石** | `TeleportUnitEffect` | 把选中的棋子传送到目标格 | `maxRange = 5`（最大传送距离） |

**共同规则**：
- **消耗 1 AP**（`GridItemData.apCost` 默认 1）
- 从**背包**使用（需先购买，见《商店》分册）
- 使用时进入 **Targeting 模式**（`GridItemManager.IsTargeting`），点击目标格确认

## 4. 数值与公式

### 4.1 网格算法

| 算法 | 方法 | 复杂度 | 说明 |
|---|---|---|---|
| **移动范围** | `GetWalkableCoords(from, maxSteps, isBlocked)` | BFS | 返回 ≤maxSteps 步内可达坐标，**不含起点自身**；**不能穿过或被阻挡** |
| **攻击范围（圆形）** | `GetCoordsInAttackRange(from, range)` | O(range²) | 返回范围内所有坐标，**含起点自身**（由调用方过滤目标） |
| **寻路** | `FindPath(from, to, isBlocked)` | BFS | 返回坐标路径；不可达返回 `null` |
| **多途经点寻路** | `FindPathWithWaypoints(from, waypoints, to, maxSteps, isBlocked)` | BFS × N 段 | 依次经过途经点，**总步数超 maxSteps 返回 `null`** |

### 4.2 两个容易搞错的边界

**① 阻挡规则：移动 vs 寻路不同**

| 场景 | 中间格被占据 | 终点被占据 |
|---|---|---|
| **移动范围**（`GetWalkableCoords`） | ✗ 不可穿过 | ✗ 不可到达（该格不进入结果） |
| **寻路**（`FindPath`） | ✗ 不可穿过 | **✓ 允许**（因为攻击目标的格子必然被占据） |

**寻路的这条例外是刻意的**：如果不允许终点被占据，就无法生成"走到敌人面前攻击"的路径。

**② 移动范围不含起点**

`GetWalkableCoords` 返回结果**不含 `from` 自身**。原因：调用方（移动 UI）用这个集合做高亮，如果含起点，起点会被错误高亮成"可移动到的格子"。

### 4.3 演算示例

**场景**：半径为 4 的棋盘，某棋子移动力 3，周围无阻挡。

```
可达格数 = 半径 4 六边形环内、距离 ≤3 的格数
         = 1 + 6×(1+2+3)
         = 1 + 6 + 12 + 18
         = 37 个候选
减去起点自身                → 36 格进入结果
```

若起点相邻 2 格有友方棋子（阻挡）：
```
BFS 到第 1 层就少 2 个入口
实际可达 ≈ 36 − 2 − (被挡方向后续 2 层约 6~8 格)
         ≈ 26~28 格
```

> **结论**：棋子站位对可达范围的影响是**非线性**的——堵住一个方向可能让后续整条支路都不可达。这是"空间是资源"的具体体现。

## 5. 数据结构（字段定义表）

### 5.1 `ChessBoardModel`（棋盘数据模型）

**类型**：纯 C# 类（**不依赖 Unity**，可单元测试）
**职责**：管理棋盘上所有存在的格子坐标 + 提供网格算法

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| 半径 | `Radius` | int（只读） | 棋盘半径；单格增删**不**自动维护 | 4 |
| 格子尺寸 | `HexSize` | float（只读） | 单个六边形的世界尺寸 | 1.25 |
| 坐标集合 | `_coords` | HashSet\<HexCoord\> | 存在性快速判定（私有） | — |
| 坐标列表 | `_coordList` | List\<HexCoord\> | 有序遍历用（View 实例化）（私有） | — |
| 坐标只读视图 | `Coords` | IReadOnlyList\<HexCoord\> | 供 View 遍历生成格子 | — |
| 格子总数 | `CoordCount` | int（只读） | 当前棋盘格数 | 61 |

**关键方法**：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Initialize` | `radius`, `hexSize` | void | 生成棋盘；触发 `OnBoardInitialized` 事件 |
| `Contains` | `coord` | bool | 坐标是否在棋盘内 |
| `SetRadius` | `radius` | void | **仅改半径记录**（整体扩展时调用） |
| `AddCoord` / `RemoveCoord` | `coord` | void | 单格增删（幂等） |
| `GetWalkableCoords` | `from`, `maxSteps`, `isBlocked` | List\<HexCoord\> | BFS 移动范围（不含起点） |
| `GetCoordsInAttackRange` | `from`, `range` | List\<HexCoord\> | 圆形攻击范围（含起点） |
| `FindPath` | `from`, `to`, `isBlocked` | List\<HexCoord\> | 寻路（终点可被占据） |
| `FindPathWithWaypoints` | `from`, `waypoints`, `to`, `maxSteps`, `isBlocked` | List\<HexCoord\> | 多途经点拼接（含总步数校验） |

> **`isBlocked` 是外部注入的谓词**（`Func<HexCoord, bool>`）：棋盘模型**不持有**任何棋子引用，占据状态由 `PieceLayoutModel` 提供权威数据。这是 Model 层解耦的关键设计。

### 5.2 `HexCoord`（坐标）

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| 列 | `q` | int | 轴向坐标横轴 | 0 |
| 行 | `r` | int | 轴向坐标纵轴 | 0 |

| 方法 | 返回 | 说明 |
|---|---|---|
| `Distance(other)` | int | 到另一格的六边形距离 |
| `Neighbor(directionIndex)` | HexCoord | 第 i 个邻居（i = 0~5） |
| `AllCoordsInRadius(radius)` | List\<HexCoord\> | 半径内全部坐标（静态） |

> 实现了 `==` / `!=` 运算符（`HexCoord` 是值类型语义，可直接作字典键）。

### 5.3 `GridItemData`（棋盘道具）

**类型**：ScriptableObject
**路径**：`Assets/Game/Resources/GridItem/*.asset`

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| 道具 ID | `id` | int | 唯一标识 | 1 |
| 显示名 | `displayName` | string | 界面显示名 | 扩展石 |
| 图标 | `icon` | Sprite | **引用型**（Inspector 配置） | — |
| 售价 | `price` | int | 商店售价 | 30 |
| AP 消耗 | `apCost` | int | 使用时消耗的行动点 | 1 |
| 效果类名 | `effectClassName` | string | `IGridItemEffect` 实现类名（工厂按名实例化） | ExpandTileEffect |
| 效果参数 | `effectJsonParams` | string | JSON 格式参数 | `{"maxRange":5}` |
| 需选中棋子 | `requiresSelectedPiece` | bool | 使用前是否必须先选中一枚棋子 | false |
| 删后最少格数 | `minTilesAfter` | int | **删除石专用**：删后棋盘剩余格数下限 | 7 |

### 5.4 `IGridItemEffect`（道具效果接口）

| 成员 | 签名 | 说明 |
|---|---|---|
| `CanExecute` | `bool CanExecute(HexCoord target, PlayerSide user)` | 校验目标格是否合法（连通性、剩余格数等） |
| （执行入口） | 由各实现类定义 | 实际改造棋盘 |

**现有实现**：`ExpandTileEffect` · `RemoveTileEffect` · `TeleportUnitEffect`

**扩展一个新道具**：新建 `GridItemData` 资产 + 实现 `IGridItemEffect` 类 → 在资产里填 `effectClassName` 与 `effectJsonParams`。**不需要改动棋盘或管理器代码**。

## 7. 边界与失败状态

| 场景 | 期望行为 | 现状 |
|---|---|---|
| 新增已存在的格 | 幂等忽略 | ✓ |
| 移除不存在的格 | 幂等忽略 | ✓ |
| 删除石把棋盘删到 < `minTilesAfter` | 拒绝执行（`CanExecute` 返回 false） | ✓ |
| 扩展石在不邻接的位置 | 拒绝执行 | ✓（保证连通性） |
| 传送石超出 `maxRange` | 拒绝执行 | ✓ |
| 寻路不可达 | 返回 `null` | ✓ |
| 多途经点总步数超上限 | 返回 `null` | ✓ |
| 终点被占据（攻击目标） | **允许**寻路到该格 | ✓ |
| 起点被写入移动范围 | **不应发生**（BFS 从起点出发、不含自身） | ✓ |
| 棋盘被删到没有格子 | **未定义** — 理论上 `minTilesAfter` 可阻止 | ⚠️ 需确认下限是否足以避免 |

## 10. 待确认项（写文档时发现的缺口）

1. **删格下限是否足够**：`minTilesAfter = 7` 能防止把棋盘删空，但**删到只剩 7 格时游戏是否还能正常进行**（部署区是否够用、寻路是否退化）未验证
2. **改造成本与收益是否平衡**：扩展石/删除石售价与 AP 消耗是否合理，未经 playtest
3. **增删格的视觉反馈**：是否有"格子出现/消失"的动画或特效，未见相关实现
