## 2. 系统概述

### 2.1 目的

装备是**构筑（Build）手段**——它让同一个棋子在两局里有不同的打法。

回答的问题：**"我给这个棋子配什么装备、能长出什么体系"**。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **装备改变行为** | 不只是加数值——吸血、反甲、免死、击杀加攻，都能改变棋子的使用方式 |
| **有取舍** | 背包只有 5 格 → 装什么必须选 |
| **组合可预期** | 被动触发时机明确（11 个钩子），玩家能预期"装上它会发生什么" |

### 2.3 在整体中的位置

```
棋子（提供基础数值与元素）
      ↓
装备（本册）— 提供属性加成 + 被动效果
      ↓
伤害计算（被动可介入）· 元素反应（IReactionModifier）· 死亡流程（免死/复活）
```

## 3. 核心规则

### 3.1 装备的数据组成

| 组成 | 字段 | 说明 |
|---|---|---|
| **标识** | `id` / `displayName` / `tier` | 分级用于商店 Tab 分类 |
| **城邦归属** | `cityState` | 城邦专属装备（`CityState` 分级） |
| **经济** | `price` | 商店售价 |
| **属性加成** | `bonusHP` / `bonusAttack` / `bonusDefense` / `bonusMoveRange` / `bonusAttackRange` / `bonusEnergyPerTurn` / `bonusAPCap` | 最后一项目前**不生效**（仅保留字段） |
| **被动效果** | `passives`（`PassiveConfig[]`） | `className` + `jsonParams` + 名称 + 唯一标记 |

### 3.2 装备分级（`EquipmentTier`）

| 分级 | 值 | 定位 |
|---|---|---|
| `Basic` | 0 | 基础（低价、纯数值） |
| `Intermediate` | 1 | 中级（带被动） |
| `Advanced` | 2 | 高级（强力被动） |
| `CityState` | 3 | **城邦专属**（只在对应城邦的商店出现） |

> **城邦专属装备池**：每个城邦有自己的（`tier = CityState`）装备池——这是"城邦差异化对局"的一部分（见城邦分册）。

### 3.3 被动效果框架

**设计模式**：`className + jsonParams → PassiveFactory 按类名实例化`（与范围 Provider、大招效果同一套范式）。

**新增一个被动效果的步骤**：
1. 写一个类实现 `IPassiveEffect`（放在 `Equipment/Effects/`）
2. 实现需要响应的钩子（其余用默认空实现）
3. 在装备资产的 `passives[].className` 填类名
4. 如需参数，填 `jsonParams`（JSON）

**不需要改框架代码**。

### 3.4 十一个钩子（`IPassiveEffect`）

**全部有默认空实现**（`{ }`）——被动**只覆写自己需要的钩子**，扩展成本极低。

| # | 钩子 | 触发时机 | 备注 |
|---|---|---|---|
| 1 | `OnEquip(owner)` | 装备到 owner 时 | 初始化用 |
| 2 | `OnUnequip(owner)` | 从 owner 卸下时 | **清理用**（如 Legion Shield 的进化态需重置） |
| 3 | `OnTurnStart(owner)` | **每次回合开始**（双方棋子都触发） | "每回合"语义 |
| 4 | `OnAttacked(owner, attacker, source)` | **被攻击时** | ⚠️ **无论是否造成减血都触发** |
| 5 | `OnDamageReceived(owner, damage, source, kind)` | **受到伤害后** | ⚠️ **仅减血时触发** |
| 6 | `OnDamageDealt(owner, damage, target)` | 造成伤害后 | **仅 `AttackPiece` 路径触发** |
| 7 | `OnKill(owner, victim)` | 击杀时 | — |
| 8 | `OnAllyDeath(owner, ally)` | 同阵营棋子死亡 | **召唤物不算队友** |
| 9 | `OnAllyUltimateCast(owner, caster)` | 同阵营释放大招后 | 协同类 |
| 10 | `OnAllyAttackHit(owner, ally, target, damage, source)` | 同阵营攻击命中后 | 协同类 |
| 11 | `UniqueId`（属性） | — | **null/空 = 非唯一被动，不参与去重** |

### 3.5 ⚠️ 两处容易搞错的语义区别

**① `OnAttacked` vs `OnDamageReceived`**

| 钩子 | 伤害被完全减免/护盾拦截时 |
|---|---|
| `OnAttacked` | **仍然触发**（"我被打了"的事实成立） |
| `OnDamageReceived` | **不触发**（没真减血） |

> **石像鬼板甲**这类"被攻击就加防"的被动用前者——如果它用后者，面对高防或护盾时会失效。

**② `OnDamageDealt` 只走普攻路径**

源码注释明确"**仅 `AttackPiece` 路径触发**"——所以大招/DoT 造成的伤害**不会**触发它。枯萎宝珠这类"攻击目标附加减益"的被动据此设计。

### 3.6 唯一被动去重（决策 D7）

**规则**：`UniqueId` 非空的被动**同名只保留一个**（后装覆盖先装）。

**⚠️ 关键约束：去重仅作用于装备被动**——角色的 `builtInPassives` **不参与去重**。

**理由**（总案 D7）：

> 角色被动是**出厂静态配置**（一个棋子配一次），不会重复，去重对其无意义；复用装备被动模板（`IPassiveEffect` + `PassiveFactory`）是合理 DRY，不拆两套。

**未来缺口**（当前不存在）：若某棋子的角色被动与装备被动**同名需互斥**，需扩展去重逻辑。当前 9 棋子的角色被动都是专属效果（且目前为空），不与装备同名。

### 4.3 属性加成的叠加方式

```
棋子有效攻击 = baseAttack + Σ(已装备的 bonusAttack)
棋子有效防御 = baseDefense + Σ(bonusDefense)
有效移动范围 = moveConfig.baseRange + Σ(bonusMoveRange)   ← 见《范围与空间》
有效攻击范围 = attackConfig.baseRange + Σ(bonusAttackRange)
```

**注意**：`bonusAPCap` **当前版本不生效**（仅数据字段保留）。

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| 同名唯一被动重复装备 | 后装覆盖先装 | ✓ |
| 非唯一被动重复装备 | 各自生效（可叠加） | ✓ |
| 角色被动与装备被动同名 | **不去重**（D7：去重仅装备被动） | ✓（有意） |
| `className` 填了不存在的类 | ⚠️ 应报错（同《范围与空间》D2 的风险） | ⚠️ 待确认 |
| `jsonParams` 非法 JSON | ⚠️ 应报错 | ⚠️ 待确认 |
| 被动卸下 | `OnUnequip` 触发 → **必须清理自身留下的状态** | ✓ |
| Legion Shield 进化态卸下 | 需重置进化状态 | ✓（设计约束） |
| 背包超容量（>5 装备） | ⚠️ 购买应被拒绝 | ⚠️ 待确认 |
| `bonusAPCap` 不生效 | 字段保留但无效果 | ✓（已知） |
