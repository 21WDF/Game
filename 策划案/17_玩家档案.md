## 2. 系统概述

### 2.1 目的

回答"**我是谁、我有什么**"——把局外的成长数据（金币、棋池）归到一个身份下。

**⚠️ 先澄清一个定位问题**：本项目是**本地双人热座 + 远期局域网联机**。

- **局域网不需要账号密码**（同一网络内直连，没有中心服务器验证身份）
- 但"玩家档案"这个**需求是真实的**：需要记住金币、已拥有棋子、战绩

**因此本系统的定位是「本地账号档案」**：保留登录窗体，实现为**纯离线校验**，并预留认证接口供将来接服务器。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **打开就能玩** | 首次启动自动创建并登录默认测试账号，**不被登录界面卡住** |
| **数据不丢** | 金币与棋池改动**即时写盘**（异常退出不丢） |
| **可多账号** | 支持多个本地账号（各自独立金币与棋池） |

### 2.3 在整体中的位置

```
玩家档案（本册）— 提供身份 + 金币 + 棋池
      ↓
局外金币经济（产出与消耗）· 大厅（显示账号/金币）· 选棋子（棋池过滤）
```

## 3. 核心规则

### 3.1 档案结构

| 字段 | 说明 |
|---|---|
| `account` | 账号（**同时作为显示名**，用户名暂用账号代替） |
| `passwordHash` | 密码哈希（**绝不明文**） |
| `passwordSalt` | 每账号独立随机盐 |
| `gold` | 局外金币余额 |
| `ownedPieceIds` | 已拥有棋子 id 列表（**棋池**） |
| `wins` / `losses` | 胜负场次（展示用） |

### 3.2 ⚠️ 密码安全（项目红线）

```
注册：生成 16 字节随机盐（Base64 存 passwordSalt）
      passwordHash = SHA256(salt + password) 的 Base64
登录：用档案内保存的盐重新计算并比对
```

**为什么即使是本地存档也必须哈希**：

> 玩家**可能在多处复用同一个密码**。如果游戏把密码明文写在本地存档里，任何能读取存档的人就拿到了一个"可能到处都在用"的密码——这**不是游戏数据安全问题，是玩家的密码安全问题**。

**实现细节**：

| 要点 | 说明 |
|---|---|
| 算法 | `System.Security.Cryptography.SHA256.Create()` |
| 盐 | **每账号独立**（16 字节随机），不是全局固定 |
| 存储 | `passwordHash` + `passwordSalt` 分开存；**数据类里没有明文字段** |

### 3.3 多账号与持久化

| 项 | 做法 |
|---|---|
| 存储介质 | `PlayerPrefs` |
| 键名前缀 | `PlayerProfile.` |
| 账号列表 | `PlayerProfile.accounts`（**全部档案的 JSON**，用 `AccountList` 包装——`JsonUtility` 不支持字典） |
| 当前账号 | `PlayerProfile.currentAccount` |

### 3.4 首次启动

**自动创建并登录默认测试账号**（`test` / `test123`，可在配置里改）→ **用户无需任何操作即可开始游戏**。

> **这条是硬要求**：调试时若每次都要输密码，体验极差；新人上手也不该被登录挡住。

### 3.5 认证接口预留（联机）

```
IAuthProvider（接口）：Login / Register / Logout / 当前账号
   ├─ LocalAuthProvider（本地实现，纯离线校验）  ← 当前使用
   └─ RemoteAuthProvider（远端实现）              ← 预留位
```

**接入服务器时只需替换实现，UI 与服务层零改动。**

## 4. 数值与公式

### 4.1 哈希流程

```
注册：
  salt = 16 个随机字节 → Base64
  hash = SHA256(salt + password) → Base64
  存 (account, hash, salt, gold=0, owned=[初始棋子])

登录：
  profile = 查找 account
  if SHA256(profile.salt + inputPassword) == profile.hash → 成功
```

### 4.2 初始棋池

**默认 4 个棋子**（取注册表中**非召唤**棋子按 id 升序前 4）：

| id | 棋子 | 元素 |
|---|---|---|
| 1 | 菲林斯 | 雷 |
| 10 | 杜林 | 火 |
| 11 | 哥伦比亚 | 水 |
| 12 | 克洛琳德 | 雷 |

> **召唤物（兔兔伯爵 id=14）被排除在棋池外**——它是安柏大招的产物，不是可上场单位。
> 具体哪 4 个**可配置**（`PlayerProfileConfig.initialPieceIds`）。

## 5. 数据结构（字段定义表）

### 5.1 `PlayerProfileData`

| 字段中文名 | 字段英文名 | 类型 | 注释 |
|---|---|---|---|
| 账号 | `account` | string | 兼作显示名 |
| 密码哈希 | `passwordHash` | string | SHA256+盐的 Base64 |
| 密码盐 | `passwordSalt` | string | 每账号独立随机盐 |
| 金币 | `gold` | int | 局外金币 |
| 已拥有棋子 | `ownedPieceIds` | `List<int>` | 棋池 |
| 胜场 | `wins` | int | 展示用 |
| 败场 | `losses` | int | 展示用 |

> 采用 `JsonUtility` 可序列化结构（`AccountList` 包装列表）。

### 5.2 `LocalAuthProvider`（本地认证）

| 方法 | 说明 |
|---|---|
| `HashPassword(password, salt)` | `SHA256(salt + password)` → Base64 |
| `Login` / `Register` / `Logout` | 见 `IAuthProvider` |

### 5.3 `PlayerProfileService`（统一服务入口，静态）

| 成员 | 签名 | 说明 |
|---|---|---|
| `Auth` | `IAuthProvider` | 当前认证实现（可替换） |
| `GetOwnedPieces()` | `List<PieceData>` | **棋池查询（统一入口）**，已过滤召唤物 |
| `GetValidPieceCount(requested)` | int | **把请求的每方棋子数钳制到已解锁范围** |
| `SettleGameOutcome(localPlayerWon)` | int | **唯一发币点**（见《局外金币经济》） |
| `BeginNewGame()` | void | **重置本局结算标志**（由 `GameFlowController.Start` 调用） |

### 5.4 `PlayerProfileConfig`（ScriptableObject）

| 字段（示意） | 说明 |
|---|---|
| 初始棋子数 | 默认 4 |
| 每局收益 / 胜利加成 | 见《局外金币经济》 |
| 棋子单价 | 500 |
| 默认账号 / 密码 | `test` / `test123` |
| `initialPieceIds` | 初始棋子 id 列表（可改） |

**全部可配** → 数值调整**改资产即可，不用碰代码**。

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| 存档损坏 / 解析失败 | 视为空列表，**重建默认档案**，绝不崩溃 | ✓ |
| 空账号记录 | 被过滤 | ✓ |
| 所有档案都无效 | 重建默认测试账号 | ✓ |
| 密码明文 | **不存在**（数据类无明文字段） | ✓ |
| 首次启动无档案 | 自动创建并登录默认账号 | ✓ |
| 金币 / 棋池变更 | **即时写盘** | ✓ |
| 账号不存在时登录 | 提示（本地场景从简，不刻意隐藏"账号是否存在"） | ✓ |
| 服务层被 UI 直接依赖 | **不应发生**（档案读写走 `PlayerProfileService`，非 UI 组件） | ✓ |
