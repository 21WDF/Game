## 2. 系统概述

### 2.1 目的

让战斗**在视觉上可读**。

回答的问题：**"谁打了谁、打得多疼、谁死了"**——在不看数值面板的情况下，光靠画面就能跟上战况。

这是设计支柱 **P4「节奏优先于表演」** 的落点：表现必须**快**（单次 ≤0.3 秒），且**不阻塞逻辑**。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **一眼看懂谁打谁** | 攻击者前冲、受击者后退——方向感明确 |
| **能看出轻重** | 重击与 DoT 的表现强度不同（位移 vs 仅抖动） |
| **死得有重量** | 死亡有下落/缩小，不是"凭空消失" |
| **不拖节奏** | 所有动作短促，不吞掉对局节奏 |

### 2.3 在整体中的位置

```
战斗逻辑（伤害/死亡/召唤）— 先完成，不等表现
      ↓ 通知
棋子表现（本册）— 纯异步视觉反馈
      ↓
DOTween 动作 · MPB 颜色 · 内置网格环绕
```

## 3. 核心规则

### 3.1 ⚠️ 前提：项目没有任何动画文件

**10 个角色 fbx 均无攻击/受击/死亡动画剪辑**（仅 2 个角色配了 Animator，且只有 `Idle`/`Walk`/`Run` 三态）。

**因此所有战斗动作都是 DOTween 程序化实现**（前冲/抖动/缩小/升起），**不是手 K 动画**。

> **这条对未来影响很大**：若想"给攻击加个帅气动画"，前提是**先解决美术素材**——当前 fbx 里没有可用剪辑。

### 3.2 ⭐ 动作宿主方案（本系统最重要的技术设计）

**问题**：实际棋子的 prefab 结构是「**根对象上同时挂着 `PieceView` + `BoxCollider` + Renderer（模型）**，子节点是骨骼层级」。

**早期方案的失败**：最初试图"把模型子节点搬到一个视觉容器里再动它"——但**模型就在根上、根本没有含 Renderer 的子节点可搬** → 容器为空 → **所有动作作用在空气上**，表现为"动作完全没生效"。

**现行方案**：给棋子根**套一个运行时父节点** `__PieceActionHost`：

```
__PieceActionHost（运行时创建，场景根对象、无父节点）
   └─ 棋子根（含 Renderer + Collider + PieceView）
        └─ 骨骼层级
```

| 要点 | 说明 |
|---|---|
| **动作作用于宿主** | 整棵树（含根上的 Renderer 与 Collider）随动 → 对"Renderer 在根 / 在子节点"两种结构**都通用** |
| **移动作用于根** | `AnimateMove` 仍操作棋子根的 `transform` |
| **两者互不干扰** | 不同 transform → `DOTween.Kill` 互不命中 |
| **运行时创建** | 不新增预制体、不改场景结构；`OnDestroy` 清理宿主 |

### 3.3 ⚠️⚠️ 坐标系铁律（踩过坑，必须遵守）

**宿主是场景根对象（无父节点）→ 它的 `localPosition` 恒等于 `position`（世界坐标）。**

**因此：一切位移必须用 `position` / `DOMove`（世界坐标语义），禁止使用 `localPosition` / `DOLocalMove`。**

**踩过的坑**：死亡动作原用 `DOLocalMove(new Vector3(0, -0.6, 0))` 想表达"相对当前位置下沉 0.6"——但因为宿主无父节点，这句被解释成"**移动到世界坐标 (0, -0.6, 0)**"，导致**棋子死亡时飞向世界原点**。召唤出现动作同理（从世界原点升起）。

**配套约定**：

| 约定 | 说明 |
|---|---|
| `BeginAction` / `EndAction` | 同时把**宿主与棋子根**都对齐到逻辑坐标（`Model.Coord` → 棋盘世界坐标） |
| 缩放（`localScale`/`DOScale`/`DOPunchScale`） | 对无父节点对象而言局部即世界，**无歧义**（可安全使用） |
| 首次构建宿主 | 打印结构诊断日志（根自身 Renderer / 子节点分布 / 动作作用对象） |

### 3.4 五个动作

| 动作 | 表现 | 时长 | 作用对象 |
|---|---|---|---|
| **攻击** | 朝目标方向前冲约 0.3 格再弹回 | **0.25 秒**（前冲 45% + 回位 55%） | 宿主 |
| **受击·完整** | 沿受击反方向位移 + 缩放脉冲 | **0.2 秒**（退 35% + 回位 65%） | 宿主 |
| **受击·轻量** | 仅缩放脉冲（**无位移**） | **0.2 秒**（脉冲取 0.7 倍） | 宿主 |
| **死亡** | 缩小到 0.02 + 下沉 0.6（世界单位） | **0.3 秒** | 宿主 |
| **召唤出现** | 由 0.05 放大到 1 + 从下方 0.3 升起 | **0.25 秒**（常量，未入配置） | 宿主 |

**✅ 上述时长已实机验收通过**（用户反馈"体验起来很舒服"）——**这是项目里第一批被实机确认的手感数值**。

### 3.5 受击分级（内聚在 `PlayHitReaction`）

**分级依据：`DamageSource` 位掩码**（不是伤害大小，而是**来源类型**）。

| 级别 | 触发来源 | 表现 |
|---|---|---|
| **完整** | `Attack` / `Splash` / `Ultimate`（普攻 / 溅射 / 大招） | 位移 + 脉冲 |
| **轻量** | `Dot` / `Reflect`（持续伤害 / 反伤） | **仅脉冲，无位移** |

**为什么 DoT 不位移**：元素格、雷暴残留等环境伤害**每回合都会结算**——如果它们也做位移，会造成**每回合全场棋子抖动**，视觉变成持续噪音，玩家分不清"这是被打了一下"还是"又到回合结算了"。

**其他守卫**：

| 情况 | 行为 |
|---|---|
| 目标已死 / 已销毁 | **不播**（死亡动作由 `DestroyPiece` 承接，避免两个动作争抢宿主） |
| 来源位置不可得 | 完整受击**退化为仅脉冲** |
| 致命伤害 | `IsDead` 守卫使受击**不播**，直接进死亡动作 —— **无动作争抢** |

### 3.6 动作触发点（全在 `PieceManager`）

| 动作 | 触发位置 |
|---|---|
| 攻击者前冲 | `AttackPiece` 结算尾部（跳字/附着/击退/金币之后、销毁判定之前） |
| 受击 | `AttackPiece`（普攻族）+ `ApplyIncomingDamage`（**所有其他伤害的统一入口**）的两处分支 |
| 死亡 | `DestroyPiece`（**全项目唯一销毁视图的入口**） |
| 召唤出现 | `SpawnPieceById`（`isSummon` 时；开局部署不播） |

> **`ApplyIncomingDamage` 是"统一伤害入口"**：大招/溅射/DoT/环境/反伤全走它。所以受击表现在这里接入一次就能**覆盖全部伤害路径**，不用在每个伤害调用点各写一遍。

### 3.7 视觉反馈四件（零素材方案）

**"零素材"= 不依赖任何图片/粒子/特效 prefab**，只用 MPB 颜色 + 内置网格实现。

| 反馈 | 实现手段 |
|---|---|
| **受击闪白** | MPB `_BaseColor` 向 `白 × 2.5` 插值（亮起再回落） |
| **元素附着光环** | 脚下圆盘（内置 `Cylinder` 压扁），颜色 = 附着元素色 |
| **反应脉冲** | 触发元素反应时光环短促放大 |
| **大招扩散** | 释放大招时脚下光环扩散并淡出 |

**光环的几何细节**：用内置 `PrimitiveType.Cylinder` 压扁成薄圆盘（**Unity 没有 Torus 图元**——曾误用 `PrimitiveType.Torus` 导致编译失败）。

```
可见半径 R → localScale = (R×2, 薄厚, R×2)
（Cylinder 原始半径 0.5，所以 ×2 后可见半径才等于配置值）
轴向本就沿 Y → 天然平铺，不需要旋转
```

### 3.8 ⚠️⚠️ 颜色通道：`_BaseColor` 三态乘法（重要约束）

**背景**：棋子用的是**自研 Toon shader**（`URPGenshinToon`），其中**不存在 `_EmissionColor` 属性**——它的 emission 分支是 `albedo × _EmissionIntensity × alpha`，**不读颜色**。

**后果**：早期"选中发光"和"受击闪白"都写 `_EmissionColor` → **静默失效**（写了不报错，但 shader 根本不读）。**"选中发光"从实现以来从未生效过**。

**现行方案**：三态全部收敛到 `_BaseColor`（shader 真实读取的属性），**乘法优先级**：

```csharp
颜色 = 白 × 选中(偏黄×1.35) × 已行动(变灰0.55)
闪白 = 向 白×2.5 插值（每帧取最新状态组合）
```

| 状态 | 效果 |
|---|---|
| 选中 | × `(1, 1, 0.6) × 1.35` → 偏黄提亮 |
| 已行动 | × `actedPieceColor`（0.55 灰） |
| 闪白 | 向 `白 × 2.5` 插值，**每帧重算回落基色** |

**复原机制**：`_selected` / `_acted` 双缓存 + `_flashPlaying` 守卫（闪白期间状态只写缓存）+ 闪白结束统一 `ApplyStateColor()` → **四种组合（选中/变灰/叠加/皆无）任意时序下都能精确复原**。

**防复发**：`SetBaseColor` 带 `HasProperty("_BaseColor")` 自校验，缺属性即告警——**杜绝再次出现"写了个不存在的属性"**。

## 4. 数值与公式

### 4.1 时长预算（P4 支柱的量化落地）

```
单次动作 ≤ 0.3 秒
已验收实测：攻击 0.25 · 受击 0.2 · 死亡 0.3 · 召唤 0.25
```

**为什么卡这个数**：移动是 0.4 秒/格。若一次"移动 2 格 + 攻击"的演出变成 0.8 + 0.5 = 1.3 秒，双方各 5 棋子、一局 20 轮 → **光演出就 4 分钟起步**。

> **调参提醒**：若实测觉得动作偏慢，优先砍 `attackDuration`（攻击是频率最高的动作）。**不要为了"更帅"而突破 0.3 秒**——那会直接蚕食单局节奏。

### 4.2 闪白强度与时长

| 参数 | 值 | 说明 |
|---|---|---|
| `hitFlashDuration` | **0.12 秒** | 闪白时长 |
| `hitFlashIntensity` | **0.8** | 峰值强度（`Color.Lerp` 的 t 系数） |
| `lightHitFlashFactor` | **0.6** | 轻量受击的强度系数 |

> ⚠️ **`hitFlashIntensity` 不要超过 1**：`Color.Lerp(state, 白×2.5, k × intensity)` 的 `t` 会被 clamp 到 1，填 5 和填 1.25 效果相同，会导致**闪白恒定满峰值、失去强弱分级**。

### 4.3 光环与扩散

| 参数 | 值 |
|---|---|
| `auraRadius` | 0.6（可见半径） |
| `auraHeight` | 0.02（离地高度） |
| `reactionPulseDuration` | 0.25 秒 |
| `ultimateSpreadDuration` | 0.35 秒 |
| `ultimateMaxRadius` | 1.5（最大可见半径） |

## 10. 待确认项

1. **`PieceAuraMaterial` 是否已创建** ⚠️：未创建时光环与扩散**静默跳过**（只有 Warning）——若用户已创建则无此问题
2. **音效素材**：4 个接入位已就绪，但**全项目零音频**——需要独立排期找素材
3. **粒子特效**：零素材方案覆盖了基础反馈，若要有"火花/烟尘"级别的表现需另找素材
4. **其他棋子的结构验证**：动作宿主方案对两种结构都通用，但**实际只验证过菲林斯**（其余 9 个棋子的 prefab 结构未逐个确认）
5. **大招释放者的表现**：释放者**不播攻击前冲**（只做扩散光环）——这是有意设计，但玩家是否能感知到"我放了大招"（除光环外）
6. **动作在移动中触发**：正常流程不会同时发生（攻击后已变灰锁定、DoT 在回合结束结算），但**防御性逻辑是否够**
7. **【已修正】`PrimitiveType.Torus`**：曾误用不存在的图元导致编译失败，现已改用 `Cylinder` 压扁——**若未来有新同事看到旧提交记录，需知道这段历史**
