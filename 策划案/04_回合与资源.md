## 2. 系统概述

### 2.1 目的

回答三个问题：**"现在轮到谁？"**、**"这一步能花多少 AP？"**、**"钱够不够买东西？"**

回合与资源系统本身不产生乐趣，它是**约束系统**——它的价值在于让"每一步都有代价"。如果 AP 无限、金币无限，那么"空间是资源"和"元素反应"都失去意义，游戏会退化成"把所有棋子的技能都放一遍"。

### 2.2 玩家体验目标

| 目标 | 具体表现 |
|---|---|
| **行动有代价** | 每一步都消耗 AP（移动 / 攻击 / 用道具），玩家需要在"多走一格"和"留着 AP 攻击"之间权衡 |
| **收支可见** | AP 与金币显示在 HUD 上，实时反映消耗 |
| **落后有补偿** | 承受伤害也能产生金币（`+0.3/点`）——被打不等于纯亏 |

### 2.3 在整体中的位置

```
回合与资源（本册）— 定义"什么时机、能动多少次、能花多少钱"
      ↓ 约束
移动 · 攻击 · 技能 · 商店 · 背包
      ↓ 反馈
经济系统（城邦：贸易/拍卖/地下交易）· 局外金币
```

## 3. 核心规则

### 3.1 回合结构

| 概念 | 字段 | 说明 |
|---|---|---|
| **Turn** | `TurnModel.CurrentTurn` | 一次单方行动（P1 或 P2 行动一次 = 一个 Turn） |
| **Round** | `TurnModel.CurrentRound` | 一个完整大轮（双方各行动一次） |
| **对局结束** | `TurnModel.IsGameOver` | 由 `CheckGameOver()` 判定 |

**事件**：
- `OnTurnStarted(int turn, PlayerSide side)` —— 某个玩家的回合开始时触发（**城邦机制、被动计时都挂在这个事件上**）
- `OnGameOver(PlayerSide side)` —— 对局结束时触发

> ⚠️ **术语提醒**：项目文档中"回合"一词**同时被用于 Turn 和 Round**（例如 `ICityStateMechanism` 的注释明确写"回合（Round）"）。写代码注释或策划案时**必须带英文**，否则极易误解——"每 4 回合衰减一次"到底是 4 个 Turn 还是 4 个 Round，差别是两倍。

### 3.2 行动点（AP）

| 规则 | 值 | 配置字段 |
|---|---|---|
| 每回合恢复 | **+2** | `GameConfig.baseAPPerTurn` |
| 上限（封顶） | **4** | `GameConfig.maxAPCap` |
| 开局 AP | 未核实（推测为 0 或上限） | ⚠️ 见 §10 |

**AP 是「按玩家独立」的资源**（`APModel._ap` 是 `Dictionary<PlayerSide, int>`）——P1 与 P2 各有自己的 AP 池，互不影响。

**AP 消耗**（各系统分别扣除）：

| 行动 | 消耗 |
|---|---|
| 移动 | 按移动格数（[PLACEHOLDER] 具体规则见《棋盘与地图》/《移动》分册） |
| 攻击 | 见《伤害计算》分册 |
| 使用棋盘道具 | `GridItemData.apCost`（默认 1） |
| 购买 | 不消耗 AP（消耗金币） |

### 3.3 金币（局内）

| 规则 | 值 | 配置字段 |
|---|---|---|
| 开局金币 | **50** | `GameConfig.startingGold` |
| 造成伤害 | **+1 / 点** | `GameConfig.goldPerDamage` |
| 承受伤害 | **+0.3 / 点** | `GameConfig.goldPerDamageReceived` |

**金币同样是「按玩家独立」的**（`GoldModel._totalGold` 是 `Dictionary<PlayerSide, int>`）。

**两种消费入口**：

| 方法 | 语义 | 用途 |
|---|---|---|
| `TrySpendGold(side, amount)` | 普通消费：余额不足则**拒绝** | 常规购买 |
| `TrySpendGoldWithOverdraft(side, amount)` | **透支消费**：可花到 `OverdraftFloor` 下限 | 贸易城邦的专属机制 |

> ⚠️ **已知设计缺口**：`OverdraftFloor`（透支下限）目前是**全城邦生效**的 ✗ —— 它本应只在**贸易城邦**下可用。且 `GoldManager.Start()` 一次性注入该值（时点早于城邦确定），要按城邦过滤需改成动态查询。**这是行为变更，尚未实施**（见 §10 与《城邦系统》分册）。

### 3.4 背包容量

| 背包 | 格数 | 配置字段 |
|---|---|---|
| 装备背包 | **5** | `GameConfig.backpackEquipmentCapacity` |
| 道具背包 | **5** | `GameConfig.backpackItemCapacity` |

**装备与道具分开计格**——同一个人可以带 5 件装备 + 5 个棋盘道具。

## 4. 数值与公式

### 4.1 AP 恢复公式

```
回合开始时：
  AP_new = min(AP_current + baseAPPerTurn, maxAPCap)

代入：AP_new = min(AP + 2, 4)
```

**关键**：这是**封顶**而非**补满**——所以连续攒 AP 最多到 4，不会累积。

| 当前 AP | 回合开始后 |
|---|---|
| 0 | 2 |
| 1 | 3 |
| 2 | **4**（封顶） |
| 3 | **4** |
| 4 | 4 |

> **设计含义**：AP 上限 4、每回合 +2 意味着**一个回合最多做两件"2 AP 的事"**，或者一件 4 AP 的大事 + 一件小事。这个上限直接决定"一回合能做多少决策"——是节奏的核心旋钮。若实测觉得玩家一回合能做的事太多，优先调这个值。

### 4.2 金币产出公式

```
造成伤害获得 = CalcGoldFromDamage(damage, goldPerDamage)          = damage × 1
承受伤害获得 = CalcGoldFromDamage(damage, goldPerDamageReceived)  = damage × 0.3
```

**演算示例**（一次 20 点伤害的交锋）：

```
攻击方：+20 × 1.0 = +20 金币
防守方：+20 × 0.3 = +6 金币
双方金币差 = 14
```

**演算示例**（一局累计，粗估）：

```
假设双方各造成 300 点总伤害、各承受 300 点：
  每个玩家收入 = 300 × 1.0（造成） + 300 × 0.3（承受） = 300 + 90 = 390 金币
  加开局 50 → 约 440 金币/局
若一件装备售价 50~100，则一局大约能买 4~8 件
```

> ⚠️ 上面是**粗估**，取决于实际伤害总量（未实测）。这个数字决定"一局能买几件装备"——即**经济是否够用**。若实测发现装备买不起，优先调 `goldPerDamage` 而不是降装备价格（因为后者会破坏跨局的价格一致性）。

### 4.3 回合数估算

```
若单局目标 20~40 分钟、每回合（Turn）约 30~60 秒：
  总 Turn 数 ≈ 20~40 个
  总 Round 数 ≈ 10~20 个
```

> 这是"单局时长"与"回合结构"的换算关系——**若 A1（单局时长）改了口径，这个估算要跟着重算**。

## 5. 数据结构（字段定义表）

### 5.1 `TurnModel`

**类型**：纯 C# 类
**职责**：回合计数 + 胜负判定 + 棋子查询

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| 当前回合 | `CurrentTurn` | int（只读） | 单方行动计数 | 3 |
| 当前大轮 | `CurrentRound` | int（只读） | 双方各行动一次为一个 Round | 2 |
| 对局结束 | `IsGameOver` | bool（只读） | 由 `CheckGameOver()` 置位 | false |

| 事件 / 方法 | 签名 | 说明 |
|---|---|---|
| `OnTurnStarted` | `event Action<int, PlayerSide>` | 某方回合开始（机制计时的挂载点） |
| `OnGameOver` | `event Action<PlayerSide>` | 对局结束，参数为获胜方 |
| `GetPieces(side)` | `List<PieceModel>` | 取某方全部棋子 |
| `CheckGameOver()` | `bool` | 判定对局是否结束 |

### 5.2 `APModel`

**类型**：纯 C# 类

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| 每回合基础 AP | `BaseAPPerTurn` | int（可读写） | 来自 `GameConfig` | 2 |
| AP 上限 | `MaxAPCap` | int（可读写） | 来自 `GameConfig` | 4 |

| 事件 / 方法 | 签名 | 说明 |
|---|---|---|
| `OnAPChanged` | `event Action<PlayerSide, int>` | AP 变化（UI 订阅） |
| `GetAP(side)` | int | 取某方当前 AP |
| `HasAP(side, amount)` | bool | 是否够花 |
| `TryConsumeAP(side, amount)` | bool | **尝试消耗**（够才扣，返回是否成功） |

> **`TryConsumeAP` 而非 `ConsumeAP`**：调用方必须先确认够不够。`APManager.ConsumeAP` 是个更外层的包装。

### 5.3 `GoldModel`

**类型**：纯 C# 类

| 字段中文名 | 字段英文名 | 数据类型 | 注释 | 示例 |
|---|---|---|---|---|
| 造成伤害金币率 | `GoldPerDamage` | float | 每点伤害的金币 | 1 |
| 承受伤害金币率 | `GoldPerDamageReceived` | float | 每点承受伤害的金币 | 0.3 |
| 开局金币 | `StartingGold` | int | 来自 `GameConfig` | 50 |
| **透支下限** | `OverdraftFloor` | int | **贸易城邦专属**（当前全城邦生效，见 §3.3） | — |

| 事件 / 方法 | 签名 | 说明 |
|---|---|---|
| `OnGoldSettled` | `event Action<PlayerSide, int>` | 金币结算（UI 订阅） |
| `GetGold(side)` | int | 取某方余额 |
| `CalcGoldFromDamage(damage, rate)` | int | 伤害 → 金币换算 |
| `TrySpendGold(side, amount)` | bool | 普通消费（不足拒绝） |
| `TrySpendGoldWithOverdraft(side, amount)` | bool | 透支消费（可到下限） |

## 7. 边界与失败状态

| 场景 | 期望行为 | 状态 |
|---|---|---|
| AP 不够就行动 | 拒绝（`HasAP` 为 false 时 UI 应禁用该操作） | ✓ |
| AP 超过上限 | 回合开始时**封顶**而非溢出 | ✓ |
| 金币不足购买 | `TrySpendGold` 返回 false，**不扣款** | ✓ |
| 金币为负（透支后） | 允许到 `OverdraftFloor` | ✓（但过滤缺失，见 §3.3） |
| 同时触发对局结束 | `CheckGameOver` 幂等（不应重复触发 `OnGameOver`） | ⚠️ 待确认 |
| 某方棋子全灭 | 判负（具体规则见《死亡与胜负》分册） | — |
| 城邦特殊败北（战争之城主将死） | 由 `WarCityManager` 判定 | ✓（见城邦分册） |

## 10. 待确认项

1. **开局 AP 是多少？** 未核实（推测为 0，第一个回合开始时 +2 得 2）——影响"第一回合能做什么"
2. **移动的 AP 消耗规则**：是"每格 1 AP"还是"一次移动固定消耗"？见《移动》分册——**这条直接影响"能走多远"的手感**
3. **透支机制未按城邦过滤** ⚠️ **这是已知的设计缺口**（§3.3）：`OverdraftFloor` 目前全城邦生效，本应只在贸易城邦下可用。修复需把 `GoldManager.Start()` 的一次性注入改为动态查询——**属行为变更，未实施**
4. **一局金币总量是否够用**：粗估约 440 金币/局（§4.2），但依赖实际伤害总量——需实测"一局能买几件装备"，若买不起应调 `goldPerDamage`
5. **AP 上限 4 是否合适**：它决定"一回合能做多少决策"，是节奏的核心旋钮（§4.1）——需实机确认
6. **回合数估算**（§4.3）依赖 A1 单局时长目标的最终口径
7. **`CheckGameOver` 的幂等性**：多次调用是否会重复触发 `OnGameOver`
